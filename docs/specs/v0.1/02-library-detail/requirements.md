# 阶段 02：存储与详情 · 需求

> 周期：W7–9
> 目标：让阶段 01 捕获到的素材「可读、可整理、可清理」——详情面板、备注、标签、原始内容复制、彻底删除、容量与保留策略、存储位置迁移，并把悬浮球补齐到三态；同时补齐阶段 01 遗留的验收门禁。
> 依据：PRD F1.8、F4.3–F4.4、F5.3、F6.1–F6.2、F6.4；技术架构 §4.5、§5.1–5.6、§8.1–8.3、§8.6；`docs/specs/v0.1/ui-contract-draft.md`（UI 前置阶段产物）；`docs/specs/v0.1/README.md` §1 门禁清单。
> **增量（2026-11-15）**：新增 P2-R15「编辑 AI 描述」与 P2-R16「编辑原文」，把详情面板里原本只读的 AI 描述、文本正文与图片 OCR 文本改为可编辑，交互复用备注的显式保存形态；保存后立即重新索引。设计与任务见 `design.md` §12、`tasks.md` Task 22–26，验收模板见 `verification.md` §6。

## 1. 本阶段要解决的问题

阶段 01 结束时，素材能进来、能看到缩略图，但进来之后什么都做不了：无法读原文、无法看原图、无法写备注、无法打标签、无法复制、无法删除，也无法知道库占了多少空间。本阶段把这些「素材的后半生」补齐。

界面部分在 UI 前置阶段已完成骨架与交互，本阶段的核心工作是把 `src/lib/api.ts` 里的 stub 逐个换成真实命令，并补齐这些命令背后的存储、文件与生命周期逻辑。**前端组件的 DOM 结构不再重做**，只做接线上必要的最小改动。

第二个目标是清掉阶段 01 的技术债：悬浮球三态、设置热生效（快捷键/尺寸）、崩溃恢复与孤儿文件、release 资源加载，以及阶段 01 验证清单里未测完的矩阵项。

第三个目标（增量，2026-11-15）：让 AI 生成的内容也能被用户纠正。详情面板里的「AI 描述」与「原文」当前只读，AI 描述错、OCR 识别错、导入正文有缺行时用户无路可走，只能重新截图或干脆不用。本次把这两块改为可编辑，交互与备注保持一致（显式保存、失败不丢文本），并在保存后立即重新索引，让修正后的文字马上可被检索。

## 2. 用户故事

1. 作为用户，我点开一条素材，能看到它的完整信息：来源应用、采集时间、尺寸、状态；文本素材能读到原文，图片素材能查看原图。
2. 作为用户，我能在详情里写备注，边打边自动保存，切走后回来内容还在。
3. 作为用户，我能给素材打标签，同一个标签可以用在多条素材上；标签在侧栏以标签云的形式汇总并显示各标签的素材数量（按标签筛选属阶段 03 的检索能力）。
4. 作为用户，我点「复制原图」后能直接粘贴到 Word / 微信 / 浏览器里；文本素材复制的是原文。
5. 作为用户，我能删掉一条不想要的素材，原图、缩略图、标签关联一起消失，且不可恢复。
6. 作为用户，我能在设置里看到库占了多少空间、上限多少，也能把整个库换到别的盘。
7. 作为用户，我能设置「只保留最近 90 天」，并在真正删除前看到会删掉多少条。
8. 作为用户，我可以把悬浮球调大调小、让它贴边收起、在全屏应用时自动隐藏，改完立刻生效。
9. 作为用户，我把快捷键改成一个没被占用的组合，改完就能按新键截图，不需要重启。
10. 作为用户，我在捕获或缩略图生成失败后能看到这条失败素材并把它删掉，而不是一条永远停在「解析中」的记录。
11. 作为用户，AI 把我这条素材描述错了，我能直接改掉它，不需要重新截图或等下一次解析。
12. 作为用户，OCR 或导入的原文有错字、缺行，我能修正它，并且改完马上能用改后的字搜到这条素材。

## 3. 可验收需求

### P2-R01 详情读取与详情面板

- 点击列表卡片打开详情面板；面板显示缩略图（图片）或类型占位、标题、来源应用、相对时间、状态、尺寸、采集时间、完整素材编号。
- 图片素材：点击缩略图在应用内 overlay 查看原图，`Esc` 关闭；原图文件缺失时显示「原图文件缺失」占位，不留白屏。
- 文本素材：显示原文前 **20000 字符**（按字符截断，不得切断 UTF-8 多字节序列），超出时末尾追加「…（已截断）」。
- 链接素材：显示原始 URL，可复制。
- AI 描述区块固定显示「待解析（阶段 03 提供）」，其复制按钮保持禁用。
- 详情读取在 ≤20 条素材的库上 P95 ≤80ms（本地 SSD，冷缓存首次读取除外）。
- 详情面板关闭后再次打开同一条素材，不出现上一条的备注草稿或标签草稿串台。

**验收方法**：图片/文本/链接各取 3 条逐项核对；手工删除原图文件后打开详情；用 2 万字以上中文文本验证截断边界（截断处前后各取一个 emoji 与汉字，确认无乱码）。

### P2-R02 备注读写

- 备注输入 300ms 防抖自动保存；`Esc`、失焦、关闭面板、切换素材时立即落盘。
- 长度上限 **10000 字符**（按字符计数，不是字节）；超出部分阻止输入，不静默截断已保存内容。
- 保存指示器四态：`编辑中 / 保存中 / 已保存 / 保存失败`；失败时保留本地文本并提示，不回滚用户输入。
- 后端 `note_set` 独立校验长度与素材存在性，超限返回 `INVALID_INPUT`，不存在返回 `NOT_FOUND`。
- 同一素材的连续保存以最后一次为准（后写覆盖），不出现旧值覆盖新值。
- 保存成功后发出 `item_note_updated { id }`，前端只失效该条详情，不整表刷新。

**验收方法**：输入 300 字后立即切换素材再切回，内容一致；输入到 10000 字再敲一个字符，输入不增长；断开库目录权限后保存，出现失败提示且文本未丢。

### P2-R03 标签

- 详情内「＋ 添加」输入标签名，回车或失焦提交；名称 trim 后为空则忽略，长度 ≤32 字符。
- 同名标签复用：大小写不敏感（`NOCASE`）比较，已存在则直接关联到当前素材，不新建。
- 移除：chip 上的移除操作解除当前素材与该标签的关联（detach），不删除标签本身。
- 标签管理：侧栏标签云支持重命名与删除；删除标签会解除其与所有素材的关联，需二次确认并显示影响条数。
- 关联到素材时记录来源：`auto`（阶段 03 自动标注）或 `manual`（本阶段全部为 manual）。自动标签被用户移除时写入 `tag_suppressions(item_id, tag_name)`，阶段 03 重新解析不得贴回。
- 标签 chip 的颜色由后端按名称散列到固定 7 色令牌返回，前端只做令牌 → CSS 变量映射，不自行取色。
- 单次标签操作 P95 ≤100ms。
- 标签云展示 `标签名 + 素材数量`，按数量降序、同数量按名称升序。

**验收方法**：同一名称大小写混输两次，确认复用同一条标签；把标签从素材移除后确认标签仍在侧栏（若已无关联，手动标签保留、自动标签清理）；重命名标签后所有关联素材显示新名。

### P2-R04 原始内容复制

- 图片素材：同时写入 `CF_DIB`（32bpp BGRA、bottom-up）与注册格式 `PNG`（完整 PNG 字节）；粘贴到 Word、微信输入框、Chrome 地址栏侧均能识别。
- 文本素材：写入 `CF_UNICODETEXT`，换行统一为 CRLF，不附加摘要/标签/来源。
- 文本素材若来自富文本拖拽（浏览器「文字 + 图片」），额外写 `CF_HTML`（片段 HTML，图片保留源站 URL），粘贴到 Word/WPS/网页编辑器时可还原图片与基本格式；`CF_HTML` 写入失败时降级为纯文本，不报错。
- 链接素材：写入 `CF_UNICODETEXT` 的原始 URL。
- 剪贴板被其他进程占用时重试 5 次 × 20ms，仍失败返回 `CLIPBOARD_BUSY`；写剪贴板失败返回 `CLIPBOARD_FAILED`；原文件不存在返回 `FILE_MISSING`。
- 成功后前端轻提示「已复制原图 / 已复制原文 / 已复制链接」；失败提示可重试。
- 复制操作不修改库内任何文件，不改变素材状态。

**验收方法**：图片复制后粘贴到 Word 与微信各一次并保存截图；文本复制后粘贴到 VS Code 确认换行正确；用另一个进程长时间占用剪贴板验证 `CLIPBOARD_BUSY` 提示。

### P2-R05 单条彻底删除

- 详情操作区删除按钮弹出确认对话框（危险样式，含素材标题），确认后执行。
- 删除内容：`items` 行、标签关联、标签抑制记录、该素材的 `jobs` 行、原图文件、缩略图文件。
- 数据库删除在单事务内完成；文件删除在事务提交后执行，失败不回滚数据库（避免「库里有、文件没了」的死循环），失败记 `warn` 并由孤儿清理兜底。
- 删除成功发出 `item_deleted { id }`；列表刷新、详情关闭、选中项清空。
- 删除后存储用量立即反映（重新查询时减少）。
- 对不存在的 id 返回 `NOT_FOUND`，界面提示「该素材已不存在」并刷新列表。

**验收方法**：删除图片/文本各一条，检查 `originals/`、`thumbs/`、`texts/` 对应文件消失，`item_tags`/`jobs` 无残留（sqlite3 手工核对）；把原图文件设为只读后删除，确认数据库已删且日志有 warn、启动孤儿扫描能计数。

### P2-R06 全库清空

- 入口在设置 → 存储 pane 底部「清空素材库」，默认折叠为危险区域，需展开才可见。
- 必须输入确认词才能提交，确认词与当前素材条数由后端提供（前端不得硬编码唯一判断）。
- 清空范围：全部 `items` 及派生数据（`item_tags`、`tag_suppressions`、`tags`、`jobs`）、`originals/`、`texts/`、`thumbs/` 下文件。
- 保留：`visrecall.db` 结构、`schema_migrations`、`settings` 表内的策略配置、`library.json`。
- 清空后发出 `items_reset {}`；列表回到空态，存储用量归零（库文件本身除外）。
- 确认词不匹配返回 `INVALID_INPUT`；清空过程失败返回具体错误码，已清空的部分不回滚（如实告知）。

**验收方法**：先建 5 条素材与 3 个标签，清空后核对表计数与目录文件；确认错误确认词被拒绝；清空后再次捕获仍可正常入库。

### P2-R07 存储用量与容量

- 用量 = `originals/` + `texts/` + `thumbs/` + `visrecall.db`（含 `-wal`）的实际字节数；条数取 `items` 计数。
- 侧栏存储条与设置存储 pane 展示「已用 / 容量 / 条数」，打开面板时读取；`item_created`、`item_deleted`、`items_reset`、`items_pruned` 后重新读取。
- 容量可设 **1–4096 GB**，默认 **50 GB**；越界返回 `INVALID_INPUT`，且不落盘。
- 容量是软配额：`已用 ≥ 容量` 时拒绝新捕获并返回 `STORAGE_FULL`，提示用户清理；**不自动删除任何素材**。
- 用量统计在 ≤20 条素材的库上 ≤150ms。
- 用量读取失败时界面显示「—」，不显示 0，不阻塞其他操作。

**验收方法**：手工计算目录大小与界面数字对账（允许 db 与 -wal 的波动）；把容量设为 1 GB 并用测试注入伪造用量超过容量，确认捕获被拒且提示正确。

### P2-R08 保留策略

- 默认「永久保留」；可选 30 / 90 / 180 天与自定义 1–3650 天。
- 选择天数后**不立即删除**；保存前弹出预估「将移除 X 条 / 释放 Y」，二次确认后才写入。
- 应用启动时执行一次过期清理（仅在非永久策略下），发出 `items_pruned { count }`；清理逐条走与 P2-R05 相同的删除路径。
- 设置 pane 提供「立即清理」，同样先显示预估再执行。
- 删除顺序按 `captured_at ASC` 逐条进行，单条失败不中断其余条目，最后汇总「成功 N / 失败 M」。
- **不做清理前 3 天预告**（与架构 §5.6 的偏差，阶段 04 复评，见设计 §1 决策表 D2-04）。

**验收方法**：把保留天数设为 1 天，构造 `captured_at` 为 3 天前的素材，重启应用确认被清理且事件可见；把库目录设为只读后清理，确认失败被如实汇报且数据未丢。

### P2-R09 存储位置查看、打开与迁移

- 设置存储 pane 显示当前库绝对路径，「打开」在资源管理器中定位（阶段 01 已有）。
- 「更换」流程：选择目标目录 → 前置校验 → 停止捕获运行时 → WAL checkpoint → 复制 → 校验 → 原子写 `config.json` → 提示「重启后生效」。
- 前置校验（任一不满足即拒绝，返回 `INVALID_INPUT` 并说明原因）：
  - 目标为绝对路径；
  - 目标不等于当前库路径，且不在当前库目录内部、当前库也不在目标内部；
  - 目标不存在，或存在且为空目录（不含任何文件/子目录）；
  - 目标卷可用空间 ≥ 源库大小 × 1.1。
- 复制 `library.json`、`visrecall.db`、`originals/`、`texts/`、`thumbs/`；逐文件记录进度事件 `storage_migration_progress { phase, done, total }`。
- 校验：目标库可打开、`PRAGMA integrity_check = ok`、`items` 行数与源一致、`library.json` 的 `library_id` 一致；任一不满足即判定失败。
- 失败：**不修改 `config.json`、不删除源目录**，恢复捕获运行时，返回结构化错误。
- 成功：源目录**不自动删除**，界面提示用户确认新库可用后可自行删除。
- 迁移期间拒绝新捕获（返回 `BUSY`），界面禁用捕获相关入口。
- **迁移成功到重启之间，捕获保持禁用**：捕获请求一律返回 `BUSY` 并提示「库已迁移，重启后生效」；不得有任何新素材写入旧库。禁用状态必须可观测：
  - `get_app_status` 新增 `restart_required: true`（前端为 `restartRequired`），刷新界面后横幅仍在；
  - 主窗口显示常驻横幅「库已迁移到 <新路径>，重启后生效；重启前捕获已暂停」，并提供「立即重启」按钮；
  - 悬浮球与快捷键仍然存在且可触发，但每次触发（含向悬浮球拖入文件）都得到明确的失败提示，而不是静默无反应。
- 重启前「打开库目录」指向**新路径**，与界面展示的库路径一致，不打开旧目录。
- 重启应用后：`restart_required = false`，横幅消失，捕获恢复，新素材写入新库。
- 迁移完成后必须重启应用才使用新库；不实现热切换。
- **WAL 与连接纪律**：`wal_checkpoint(TRUNCATE)` 必须在停止写入、且没有任何其他连接持有读快照时执行。迁移过程中的校验与统计连接只能对**目标库**打开，不得对源库另开连接；checkpoint 返回值非 0（未清空）视为迁移失败，不进入复制。
- 不实现显式断点续传文件：重试时按「目标已存在且大小一致则跳过」天然续传。

**验收方法**：迁移到同盘新目录与另一块盘各一次，核对文件数/字节数/条数；迁移到非空目录、迁移到自身子目录、目标盘空间不足三种拒绝路径各验一次；复制中途失败（把目标目录设为只读）后确认原库仍可用、`config.json` 未改；**迁移成功后按快捷键与点悬浮球各一次，确认旧库条数不变、出现「库已迁移，重启后生效」提示、横幅在刷新界面后仍在；重启后确认捕获恢复且新素材落在新库**；用 Python 另开一条连接并持有读事务后发起迁移，确认因 checkpoint 未清空而返回 `BUSY` 且目标目录无文件。

### P2-R10 悬浮球三态与显示设置

- 尺寸三档 **40 / 48 / 56**（逻辑像素），设置修改后**立即生效**，无需重启；改尺寸后球保持在工作区内。
- 贴边收起：距工作区边缘 ≤12px 松手后静置 800ms → 收为 5px 宽、长度等于球尺寸的长条（带 1px 描边）；长条本身不作为唯一命中区，另设 6px 外扩热区。
- 悬停展开：鼠标进入热区后 150ms 内滑出球形态；离开 600ms 后回缩长条。
- 全屏自动隐藏：检测到全屏/演示/D3D 独占状态时隐藏，退出后恢复；开关可关闭。检测失败按「非全屏」处理。
- 首次运行引导：一次性轻提示（主窗口 Toast + 设置入口高亮），展示后持久化，不再重复。不使用独立气泡窗口（D2-07）。
- 关闭悬浮球后，快捷键捕获、拖放入库其余能力不受影响。
- 捕获会话期间球被隐藏、结束恢复的既有行为不得回退。

**验收方法**：三档尺寸各切换一次并截图对比；把球拖到屏幕边缘确认收起/展开；打开全屏视频与 PPT 放映各一次验证隐藏与恢复；删除配置里的引导标记验证只出现一次。

### P2-R11 设置热生效

- 快捷键：解析失败返回 `INVALID_INPUT`（说明格式）；组合键被占用返回 `INVALID_INPUT`（说明被占用）且**保留旧值**，旧快捷键继续可用。
- 快捷键修改成功后立即生效，不需重启；托盘 tooltip 的冲突提示同步清除。
- 悬浮球开关、尺寸、贴边、全屏隐藏均立即生效。
- 设置写入磁盘失败时，内存与界面均保持旧值（先写盘后改内存）。
- 全部设置为原子写入（临时文件 + rename），损坏文件回退默认值的行为不回退。

**验收方法**：改成 `Ctrl+Alt+Shift+F9` 后立即按键验证；用另一程序占用 `Ctrl+Shift+S` 再改回该键，确认拒绝且原键仍可用；把 `config.json` 设为只读后保存，确认提示且界面回退。

### P2-R12 崩溃恢复与孤儿文件

- 启动时 `jobs.running → queued` 的恢复逻辑保留，恢复条数 > 0 时发出 `app_recovered`。
- 启动清理 `tmp/` 的行为保留。

- **数据库文件不可分隔**：`visrecall.db`、`visrecall.db-wal`、`visrecall.db-shm` 同属一个数据库，应用不提供单独删除、移动或“压缩”它们的入口；「清理孤儿文件」的扫描范围严格限定在 `originals/`、`texts/`，绝不触碰数据库文件与 `library.json`。
- 设置存储 pane 需用一句话说明上述约束（库目录对用户完全可见，必须防误删）。
- 「清理孤儿文件」需二次确认，显示文件数与字节数；只删除确实不被引用的文件，删除失败逐条记录不中断。
- 缩略图缺失时：卡片与详情显示类型占位，不报错、不阻塞列表。
- 迁移中断（进程被杀）后重启：仍打开原库（`config.json` 未被改），目标目录残留文件由用户手动清理，界面不误报。

**验收方法**：强杀进程后重启核对恢复日志；手工在 `originals/` 放一个未入库文件，确认孤儿计数 +1 并可清理；手工删除某条缩略图后打开列表与详情；**清理孤儿文件前后比对 `visrecall.db`、`-wal`、`-shm` 均未被修改或删除，且素材条数不变；确认设置存储 pane 存在“数据库文件请勿单独删除或移动”的提示文案**。

### P2-R15 编辑 AI 描述

- 展示：有摘要时该区块就是备注式的常驻 textarea（与备注共用同一套模板与过渡），聚焦或有未保存改动时显示「取消 / 保存」；不做自动保存与乐观更新。
- 识别状态（`summary IS NULL`，即待解析）不提供编辑，只显示占位文案与禁用的「复制」。
- 长度上限 **2000 字符**（按字符计，不是字节）；前端阻止超出输入，后端超限返回 `INVALID_INPUT` 并保留旧值，不静默截断。
- 保存语义：写 `insights.summary`，同时置 `summary_user_edited=1`；**`summary_source` 保持原值**（`vlm` / `ocr` / `extractive` / `none` 不变），界面不显示「已编辑」徽标——本次明确不做来源标记与旧值恢复。
- 摘要为空的素材（`summary IS NULL`）也允许手动补写；写入后 `summary_source` 仍为 `none`，面板不显示来源徽标。
- 保存成功后触发元数据钩子（`bump_revision` + 入队 `index`，与备注同一条路径）：FTS `summary` 列与语义向量 document 立即反映新文本，新措辞可被检索到；发 `item_content_updated { id, field: "summary" }`，前端只失效该条详情（摘要不影响卡片，不刷新列表）。
- **写入保护**：`summary_user_edited=1` 的素材，后续 VLM/文本 Provider 重新解析、`content_hash` 复用、占位摘要三条写入路径都不得覆盖已编辑摘要（其余字段如颜色/类型/标签照常更新）。
- 保存失败（只读库、磁盘错误）返回 `IO` / `DATABASE`，前端保留输入文本并提示可重试；素材不存在返回 `NOT_FOUND`。
- 切换素材或关闭面板时，未保存草稿丢弃并回填库内值，不出现串台。

**验收方法**：把一条 VLM 摘要改成含唯一词「蓝鲸」的句子并保存，立刻用「蓝鲸」检索能命中；重启应用后摘要不变；在集成测试里注入一次 VLM 解析结果，确认已编辑摘要未被覆盖；把库目录设为只读后保存，确认提示且文本未丢。

### P2-R16 编辑原文

- **文本素材正文**：库内正文就是备注式的常驻 textarea（与备注共用模板），聚焦或有未保存改动时显示「取消 / 保存」；保存写回库内 `texts/*.txt`（原子写：临时文件 + rename，失败不留半文件），刷新 `items.updated_at` 并触发 `bump_revision` + 入队 `index`。
- 外部引用素材不提供编辑：只读展示正文并提示「该素材引用外部文件，原文只读」。
- 顺序约束：文件写成功后再更新 revision / 入队；文件写失败不得递增 revision、不得发事件，返回 `IO`。
- 正文长度上限 **20000 字符**（与详情展示的 `BODY_TEXT_LIMIT` 一致）。详情返回 `body_text_truncated=true`（原文超过 20000 字符）时**禁止编辑**，UI 显示只读与原因，避免把截断内容写回文件造成数据丢失。
- **外部引用素材不可编辑**：`external_asset_for_item(id)` 有值时详情返回 `body_text_editable=false`，界面禁用编辑并提示「该素材引用外部文件，原文只读」；后端收到写请求返回 `INVALID_INPUT`。
- **图片素材 OCR 文本**：有识别文本时「识别到的文字」区块就是备注式的常驻 textarea（`insights.ocr_text`，上限 20000）；未识别到文字时不提供编辑，只显示「未识别到文字」。保存后置 `ocr_user_edited=1`，**不修改 `ocr_boxes_json`**——没有坐标来源，不重算文字框；界面固定提示「手工修改后，原图文字框仍按上次识别结果标注」。
- OCR 文本长度上限 **20000 字符**；详情返回 `ocr_text_truncated=true` 时禁止编辑（同一保护原则）。
- 保存成功后同样触发元数据钩子，FTS `ocr_text` 列与语义 document 立即更新；发 `item_content_updated { id, field: "ocrText" | "bodyText" }`，前端失效该条详情；正文编辑额外失效列表首页（卡片预览来自正文），OCR 编辑不刷新列表。
- **写入保护**：`ocr_user_edited=1` 的素材，后续 OCR 重新识别不得覆盖 `ocr_text` 与 `ocr_boxes`（引擎、置信度等元数据可更新）。
- 空文本允许保存（清空原文）；清空后详情显示空态，检索不再命中该素材的旧正文。
- 正文文件缺失（`body_text` 为 `null`）时仍允许编辑并重建文件；图片素材没有 `insights` 行时同样允许补录 OCR 文本（保存时建行）。
- 原文与「识别到的文字」提供一键复制；无文本时复制按钮禁用。

**验收方法**：改一条文本素材正文并加入唯一词「海獭」，确认卡片预览与检索立即反映、重启后仍在；把 `texts/` 设为只读后保存，确认报错且 revision 未变；对外部引用素材确认编辑按钮禁用；改一条图片 OCR 文本后确认原图文字框仍显示、检索按新文本命中。
