# 阶段 01：捕获闭环 · 需求

> 周期：W3–6  
> 目标：在没有 AI 的前提下，完成「触发 → 冻结帧 → 识别 → 选区 → 裁剪落盘 → 入库 → 列表可见」的完整闭环，并具备可日常使用的悬浮球与拖放入口。  
> 依据：PRD F1.1–F1.5、F1.8、F7.2、F7.3（部分）、F6.1（默认路径）；技术架构 §3、§4、§5.1–5.4、§8。
>
> **测试规模口径（2026-11-06 追注）**：本文中的「100 条」是阶段 01 当时的验收口径，未实际执行。
> 阶段 02 起统一按 **≤20 条** 执行（见 `../README.md` §3 与 `../02-library-detail/verification.md` §0.1）；
> P1-R07 中「超过 200 条时在阶段 02 引入虚拟滚动」在阶段 02 明确不执行（见 `../02-library-detail/design.md` §1.2）。

## 1. 本阶段要解决的问题

用户按下快捷键或点击悬浮球后，能在 150ms 内看到冻结画面；用鼠标选中窗口或框选区域，确认后素材被保存到本地库，并以「解析中 → 正常」的状态出现在主窗口列表中。全程不联网、不依赖 OCR/VLM。

本阶段结束时，即使阶段 03 尚未开始，用户也可以持续捕获并浏览素材；列表中的「正常」只代表缩略图已生成，不代表已完成 AI 解析。

## 2. 用户故事

1. 作为用户，我按下 `Ctrl+Shift+S` 或点击悬浮球，能立即看到屏幕冻结并进入选区态。
2. 作为用户，我把鼠标移到某个窗口上，能看到该窗口被高亮；点击即选中，或直接拖拽框选任意区域。
3. 作为用户，我能用八个控制点、拖动内部、方向键微调选区；靠近窗口边缘时能自动吸附。
4. 作为用户，我按 `Enter` 或点击 ✓ 后，选区被保存为原分辨率图片，并在主窗口列表中看到它。
5. 作为用户，我按 `Esc` 或右键可以取消，不产生任何记录。
6. 作为用户，我可以把图片文件、`.txt`/`.md`、选中的文字或链接拖到悬浮球，直接入库。
7. 作为用户，关闭主窗口后应用仍在托盘运行；再次打开时能看到之前的素材。
8. 作为用户，我在多显示器、150% 缩放下框选，保存的图片边界与选区一致，不偏移。

## 3. 可验收需求

### P1-R01 应用骨架与单实例

- 应用以 Tauri 2 + React 19 + TypeScript 运行，单进程。
- 第二次启动不创建新进程实例，而是唤醒已有实例的主窗口并退出。
- 托盘图标存在，菜单至少包含「打开主窗口 / 显示或隐藏悬浮球 / 设置（占位）/ 退出」。
- 关闭主窗口不退出进程；主窗口隐藏后托盘仍可用。
- 主窗口关闭 60 秒后销毁 WebView2 与窗口；再次打开重新创建，允许 300–800ms 骨架屏。
- 冷启动到托盘可用 ≤2s（目标机器实测，机械盘 4s）。

**验收方法**：手工启动两次、关闭/重开主窗口、任务管理器确认 `msedgewebview2.exe` 在关闭 60s 后退出；记录启动耗时。

### P1-R02 全局快捷键

- 默认捕获快捷键 `Ctrl+Shift+S`，注册使用 `RegisterHotKey` + `MOD_NOREPEAT`，独立消息循环线程。
- 快捷键触发与悬浮球单击触发产生相同的 `CaptureRequest`。
- 快捷键被占用时，设置中（阶段 02 完整 UI）能提示冲突；阶段 01 至少在日志与托盘提示中可见。
- 快捷键线程只投递事件，不做抓帧或 IO。

**验收方法**：注册后按快捷键出现覆盖层；用其他程序占用同一组合键时启动日志出现明确错误码；连续快速按键不排队重复触发（`MOD_NOREPEAT`）。

### P1-R03 冻结帧与抓帧

- 触发后、显示任何应用自有窗口之前，记录前台窗口（PID、进程名、显示名、窗口标题、显示器）。
- 隐藏悬浮球、提示气泡等自有窗口，调用 `DwmFlush`，再抓取每个显示器的一帧。
- 主路径使用 GDI：`GetDC(NULL)` + `BitBlt` 到 32 位 DIB section；每抓完一个显示器立即上传为 D3D11 纹理并释放 CPU 位图。
- 冻结帧在选区过程中保持不变；覆盖层直接采样纹理，不重新抓屏。
- 抓帧失败重试一次；仍失败进入实时模式，覆盖层角标显示「实时模式」。
  - **阶段 01 已确认降级**：实时模式（透明覆盖层 + 提交时现场抓取）不实现；重试仍失败时以 `CAPTURE_FAILED` 事件与托盘提示反馈，记录为已知限制，阶段 02 再评估实现。
- 全黑帧（疑似 DRM）丢弃并提示「该窗口无法截取」，不产生记录；部分显示器全黑时只丢弃该屏，全部全黑才整次失败。
- 双 4K 抓帧期间进程工作集增量目标 ≤100MB；CPU 峰值只保留一个显示器的原始位图。

**验收方法**：单屏/双屏、4K/1080p、150% 缩放；用 ETW/任务管理器记录抓帧前后工作集；打开 DRM 视频窗口验证丢弃路径；断网不影响抓帧。

### P1-R04 窗口识别与层级

- 枚举顶层窗口时过滤不可见、cloaked、工具窗口；使用 `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` 获取精确边界。
- 鼠标命中通过 `WindowFromPoint` + `RealChildWindowFromPoint` 得到从根到子的窗口链。
- 桌面空白（`Progman` / `WorkerW` / `Shell_TrayWnd`）识别为整屏。
- 滚轮在父/子窗口间切换高亮层级；每次切换重新计算高亮矩形与标签。
- 标签显示窗口标题、类名、进程显示名、宽高。
- 窗口识别准确率目标 ≥95%（用 100 张以内的真实桌面场景人工核对）。

**验收方法**：在 Chrome、Word、资源管理器、微信、VS Code 上移动鼠标与滚轮切换；核对标签与保存边界；记录失败场景。

### P1-R05 覆盖层与选区

- 每个显示器一个无边框置顶窗口，尺寸等于该显示器物理像素；使用 D3D11 swap chain + Direct2D 渲染。
- 选区外压暗；选区显示实线边框、八个控制点、实时尺寸标签；左上角「已冻结」角标 3s 后淡出。
- 支持：拖拽新建选区、拖动内部整体移动、八向控制点缩放、方向键 1px、`Shift`+方向键 10px、距窗口边缘 8px 吸附、`Ctrl` 临时关闭吸附。
- 最小选区 10×10px；小于该值提交时取消并提示「选区过小」。
- `Esc` 或右键取消；`Enter` 或点击 ✓ 提交。
- 跨屏选区按物理像素合并，每个覆盖层只绘制与自己相交的部分；起始点须落在某一屏内。
- 覆盖层显示时获得键盘焦点；退出后把焦点还给原窗口。
- 选区交互 60fps；高亮跟随 ≤50ms（4K 单屏、拖动控制点场景）。

**验收方法**：单屏/双屏/混合 DPI（100/125/150/200%）、跨屏拖拽、吸附开关、键盘微调；PresentMon 记录帧时间；保存图与选区逐像素比对边界。

### P1-R06 裁剪、落盘与入库

- 提交时只从冻结帧纹理回读选区（staging texture），不重新抓屏。
- 编码为 PNG；原图路径 `originals/images/YYYY/MM/<uuid>.png`，数据库存相对路径。
- 写入流程：`tmp/<uuid>.tmp` → `fsync` → `rename` 到目标路径 → 插入数据库；任一步失败清理临时文件。
- 插入 `items` 后状态为 `parsing`，立即发出 `item_created` 事件；缩略图完成后转 `ready`。
- 同一画面重复捕获按普通素材入库，不去重、不提示。
- 提交后覆盖层立即关闭，落盘/入库/缩略图异步进行，不阻塞下一次捕获。

**验收方法**：提交后 ≤3s 列表出现可读缩略图；强制结束进程后重启，已落盘但未入库的临时文件被清理或可恢复；检查数据库路径为相对路径。

### P1-R07 素材列表

- 主窗口显示素材网格，按 `captured_at DESC` 排序；keyset 分页，每页默认 50，顶部加载更多。
- 卡片显示缩略图、状态（解析中/正常/失败）、来源应用、捕获时间；图片缺失显示占位。
- 新素材通过事件使 TanStack Query 缓存失效并出现在列表顶部。
- 列表在 100 条以内直接渲染即可，滚动流畅；超过 200 条时在阶段 02 引入虚拟滚动。
- 空状态有明确引导（「按 Ctrl+Shift+S 或点击悬浮球开始捕获」）。

**验收方法**：连续捕获 100 条以内素材，检查顺序、分页、状态变化与滚动；断网不影响列表。

### P1-R08 悬浮球（阶段 01 最小可用）

- 原生分层窗口（`UpdateLayeredWindow`，32 位 ARGB），置顶、`WS_EX_TOOLWINDOW`、`WS_EX_NOACTIVATE`，不进任务栏/Alt-Tab，不抢焦点。
- 默认 48px 圆形；单击触发捕获；按住拖动移动位置；位置按显示器记忆并持久化。
- 拖拽进入球体时放大到 1.15 倍并显示动作提示（「存为图片」/「存为片段」/「存为链接」/「导入 N 个文件」）。
- 阶段 01 不要求贴边收起、悬停展开、全屏自动隐藏、首次引导气泡；这些在阶段 02 完整实现。
- 设置中关闭悬浮球后，快捷键仍可完成捕获（阶段 01 可先通过配置文件开关）。

**验收方法**：单击触发、拖动后重启位置恢复；置顶且不抢焦点；拖放进入时视觉反馈正确；关闭后快捷键可用。

### P1-R09 OLE 拖放

- 悬浮球注册 `IDropTarget`（`OleInitialize` + `RegisterDragDrop`），支持 `CF_HDROP`、`CF_UNICODETEXT`、`CF_HTML`、`CF_DIB`/PNG。
- 图片文件（PNG/JPG/WebP/GIF）：每张一条图片素材；单文件 ≤20MB；长边 >8000px 用 WIC 降采样后入库。
- 文本文件（.txt/.md）：每份一条文本素材；≤500KB；UTF-8 优先，失败回退 GB18030；标题取文件名或首个一级标题。
- 文本/HTML 片段：剥离格式；≤10000 字符，超出拒绝并明确提示，不截断。
- 单个 URL：存为链接素材，抓取页面标题/站点名，超时 5s，失败回退 URL。
- 混合图片 + 文本：图片优先，文本写入备注。
- 文件夹/快捷方式/压缩包/PDF/Office：拒绝，气泡列出支持格式，不产生记录。
- 批量 ≤20 个；逐文件校验，部分失败不影响其他文件。
- 拖拽中按 `Esc` 或移出球体取消，不产生记录。

**验收方法**：从 Chrome 拖选中文字、Word 拖文本、资源管理器拖图片、微信拖图片四类来源实测；验证超限、编码、批量与取消路径。

### P1-R10 本地库与配置

- 默认库目录 `%USERPROFILE%\Documents\VisRecall\`；包含 `library.json`、`visrecall.db`、`originals/`、`texts/`、`thumbs/`、`tmp/`。
- `library.json` 写入 `library_id`、`format_version`、`created_at`；格式版本高于客户端时拒绝打开并提示升级。
- 配置文件 `%APPDATA%\VisRecall\config.json`，原子写入（临时文件 + rename）；读取失败回退默认值并提示。
- SQLite 使用 bundled + WAL + `foreign_keys=ON` + `busy_timeout`；应用启动时清理 `tmp/` 与孤儿文件。
- 数据库文件路径一律为相对路径。
- 设置中可查看库路径并一键打开所在文件夹（完整位置迁移在阶段 02）。

**验收方法**：首次启动创建目录与文件；手动改高 `format_version` 验证拒绝；移动库目录后相对路径仍可用；删除 `tmp/` 文件后启动清理不报错。

### P1-R11 错误可见与恢复

- 捕获失败、抓帧失败、落盘失败、拖放解析失败都必须有用户可见反馈（托盘通知或主窗口提示），并带结构化错误码。
- 失败不静默；不因单次失败导致应用退出。
- 启动时把 `jobs` 表中 `running` 的任务改回 `queued`（阶段 01 可只建表与恢复逻辑骨架，阶段 03 接入真实任务）。
- 日志使用 `tracing`，不记录截图内容、OCR 全文、API Key。

**验收方法**：模拟只读目录/磁盘满、拒绝拖放格式、强杀进程后重启；检查提示与日志。

### P1-R12 性能与内存（阶段 01 门禁）

| 指标 | 目标 | 测量 |
|---|---|---|
| 捕获入口响应 | ≤150ms | 快捷键时间戳 → 覆盖层首帧 Present |
| 选区交互 | 60fps；高亮跟随 ≤50ms | PresentMon / 帧时间 |
| 提交到列表可见 | ≤3s（100 条以内库） | 提交时间 → 缩略图事件 |
| 托盘常驻内存 | ≤150MB（目标 40–70MB） | 主窗口关闭 60s 后私有工作集，无 WebView2 进程 |
| 4K 双屏抓帧增量 | ≤100MB | 抓帧前后工作集快照 |
| 空闲 CPU | <1% | 托盘空闲 10 分钟 PerfMon |

## 4. 明确不做（阶段 01）

- OCR、嵌入、VLM、检索、查询解析（阶段 03）。
- 详情面板、备注编辑、标签编辑、复制原图/原文、删除、保留策略（阶段 02）。
- 收件箱、合集、时间线、星标、批量操作（PRD 明确 V0.1 不做）。
- 剪贴板捕获、捕获后备注浮层、公式、导出、迁移、本地 VLM。
- 自定义标题栏；使用原生标题栏。
- 万级素材压测与容量评测。
- ARM64 产物（阶段 04）。

## 5. 阶段退出条件

1. 上述 P1-R01–P1-R12 全部通过或记录经确认的降级路径。
2. 捕获闭环在目标机器上连续使用 30 分钟无崩溃，完成 ≥20 次真实捕获。
3. 100 条以内素材列表滚动、状态更新正常。
4. `cargo test --workspace`、`pnpm typecheck`、`pnpm build` 全部通过。
5. 手工验收矩阵记录在 `01-capture-loop/verification.md`。
6. 已知限制（DRM、提权窗口、独占全屏、ARM64）在文档中列明。
