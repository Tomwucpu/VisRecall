# 阶段 03：AI 与检索 · 需求

> 周期：W10–13
> 目标：让素材「可搜、搜得准、搜得快、知道为什么搜到」——OCR 与本地嵌入打通离线检索底座，云端 VLM 做两阶段增强，FTS+向量+过滤三路 RRF 融合，命中解释与 OCR 高亮形成产品差异化；同时交付 50 条查询评测集与 Top-3 ≥80% 的质量门禁。
> 依据：PRD F2.1–F2.4、F3.1–F3.4、F7.1；《VisRecall-技术架构设计 v1.2》§5.2、§5.3、§6、§7；《VisRecall-阶段三-AI与检索架构设计 v1.0（定稿 2026-11-08）》——决策 A1/A2/B1/B2/B3/C1/C2/C3/D1/D2/D3/D4/E1 以该文档为准，本文只做需求化表述。
> 上游遗留：阶段 02 遗留的「标签云点击筛选」「hue-dot 真实数据」「20 条数据视觉验收」在本阶段收口（见 P3-R10、§5）。

## 1. 本阶段要解决的问题

阶段 02 结束时，素材能捕获、能读、能整理、能清理，但**进得来、出不去**：列表只有时间倒序一种浏览方式，超过一屏的素材等于丢失。摘要区固定显示「待解析」，标签全靠手打。本阶段补上素材的「前半生」——理解与索引，以及整个产品的核心命题——检索。

三条硬指标定义了本阶段的形态：

1. **新鲜度**：提交后 ≤3s（P95）可检索。参考项目全部是「索引完才可搜」，这是我们的差异化，靠两阶段索引实现。
2. **离线**：查询路径（解析/FTS/嵌入/向量）零网络。嵌入模型必须本地、必须小；云端 VLM 只在入库侧。
3. **可解释**：每条命中回答「为什么搜到」。五个参考项目都没有这个能力。

## 2. 用户故事

1. 作为用户，我刚截了一张报错截图，几秒后在搜索框输入报错关键词就能找到它，不需要等「AI 处理完」。
2. 作为用户，我能输入「上个月的橙色漏斗图」这样的自然语言，时间、颜色、图表类型被识别成筛选条件并回显为 chip，删掉某个 chip 结果会重新计算。
3. 作为用户，我能搜发票号、报错原文、界面按钮文字这类字面内容，结果里能看到命中的词（snippet 高亮）。
4. 作为用户，我换个说法（「一张关于定价的深色界面」）也能搜到目标截图，即使图上没有这些字。
5. 作为用户，我点开一条结果，能看到它为什么被搜到：命中了哪些筛选条件、哪些词、还是仅语义相关；OCR 命中的词在预览图上有高亮框。
6. 作为用户，断网或没配 API Key 时我仍然可以捕获和检索，只是摘要是 OCR 摘录且明确标注来源；配好 Key 后自动增强替换。
7. 作为用户，我在设置里配置模型服务地址与密钥，密钥存进 Windows 凭据管理器，界面里永远看不到明文；保存前能一键探测连通性与视觉能力。
8. 作为用户，主模型服务失败时自动切备用模型；密钥错误（401/403）被明确告知是配置问题，而不是无限重试。
9. 作为用户，我点侧栏标签云里的标签，列表立刻按该标签筛选。
10. 作为用户，图片卡片的角落能看到主色圆点，与我用颜色词搜索的口径一致。
11. 作为用户，素材列表卡片上能看到 AI 摘要的第一行与自动标签（带「自动」角标），我删掉的自动标签不会被重新贴回。
12. 作为用户，文本片段和链接也能被搜到：原文进全文索引，语义通道覆盖换说法的查询。

## 3. 可验收需求

### P3-R01 OCR（图片理解主路径）

- PP-OCRv5/v4 mobile ONNX（`ort` CPU 推理，det+rec 两模型）为主路径；PP-OCR 不可用（模型文件缺失/校验和不符/初始化失败）时自动降级 Windows.Media.Ocr；两者都不可用时该素材无 OCR 文本，仅元数据/备注可搜，状态不阻塞。
- 模型文件随仓库/安装包分发（合计约 10–20MB），启动时校验 sha256，与清单不符记 `warn` 并走兜底路径，不崩溃。
- OCR 结果落 `insights`：`ocr_text`（全文）、`ocr_boxes_json`（归一化包围盒 + 每框文本）、`ocr_engine`、`ocr_confidence`；整体置信度 <0.6 在详情中标注「OCR 置信度低」。**无文字属正常结果而非失败**：`ocr_text`/`ocr_confidence`/`boxes` 落 NULL/空，不触发低置信标注，占位摘要不写（`summary` 保持 NULL、`summary_source='none'`），`index`/`vlm` 任务照常——无字图正是 VLM 语义通道的目标场景，离线时仅元数据/备注可搜（架构文档 §6.2 已接受的取舍）。
- 典型 UI 截图 OCR 耗时 300–1500ms（CPU），纳入 ≤3s 新鲜度预算；单张 4K 截图 OCR ≤4s（P95，超长图允许降采样）。
- 字符准确率门禁：100–200 张真实截图抽样 ≥97%（T0 spike 与阶段验收各测一次，口径见 verification §1）。
- 文本/链接素材不走 OCR。

**验收方法**：用 20 张不同来源（IDE、浏览器、微信、设置页、含表格截图）的真实截图跑 OCR，逐张与人工标注比对计算字符准确率；删除一个模型文件验证降级与 `warn`；构造一张无文字纯色图验证空结果不报错。

### P3-R02 本地嵌入（语义通道底座）

- 嵌入模型 bge-small-zh-v1.5，ONNX int8 量化，512 维，向量以 int8 BLOB 存储；`model_id` 与 `dim` 固定于库（`settings`），同一库内不得混用向量空间。
- 嵌入在查询路径上：**零网络**。模型懒加载 + 启动后台预热；未就绪期间检索降级为 FTS+过滤并在状态栏标注，加载完成自动恢复（事件驱动，无需重启）。
- 性能门禁：模型加载后单条嵌入 <30ms；模型常驻内存增量 ≤60MB（主窗口场景）。
- 查询向量 LRU 缓存（容量 256，命中不重算）。
- search document 构造：`标题 > 摘要 > 标签 > 实体 > 备注 > OCR/原文` 按序拼接，512 token 预算内截断（字段顺序即保留优先级）；文本/标签/备注变更只重嵌入不重跑 VLM。

**验收方法**：对同一文本嵌入两次结果一致（确定性）；「相关的两个文本」余弦相似度高于「不相关的两个文本」（语义 sanity）；记录模型加载耗时与内存增量；缓存行为用同一查询连发两次验证第二次耗时显著下降。

### P3-R03 云端 VLM 增强（两阶段第二阶段）

- OpenAI 兼容 chat/completions 接口（可配 base URL 与模型名）作为 `VisionProvider`（图片）与 `TextProvider`（文本摘要）；主备两组配置。
- 图片素材：摘要、标签（≤8 个，去停用词）、`content_type`/`primary_color`/`chart_type`/`ui_type` 结构化属性、实体列表、公式（`latex` + `has_formula`）、置信度。
- 文本素材：摘要 + 标签。
- 云端增强受「设置 → 模型」中的「图片上传云端解析」「文本上传云端解析」开关控制，默认关闭；关闭时只做本地 OCR、FTS 与向量索引，不发起云端请求。
- 返回 JSON 严格 schema 校验：解析失败时把错误信息回传模型**修复一次**，仍失败按本次调用失败处理（走重试/主备），不落脏数据。
- VLM 失败/离线：OCR 摘录占位（`summary_source='ocr'`，取 `ocr_text` 前 280 字符），素材 `status='pending'` 可重试；**不在启动或恢复时自动重试**，由用户在详情面板点「重新解析」手动触发（2026-11-09 变更）。
- VLM 成功：`summary_source='vlm'`，`status='ready'`；自动标签以 `origin='auto'` 关联，写入前过滤 `tag_suppressions`（用户删过的自动标签不回贴），同名标签复用既有行。
- 401/403 判定为配置错误：任务终止重试、UI 明示「密钥或地址配置错误」，其他 5xx/超时走指数退避。
- 阶段一（OCR/临时嵌入）不受 VLM 任何状态影响：无 Key 时新捕获依旧 ≤3s 可检索。

**验收方法**：配一个真实 Key 走全流程核对 schema 全字段；返回畸形 JSON 验证修复一次与失败路径；断网捕获验证 OCR 摘录占位与 `pending` 状态；删掉一个自动标签后触发重新解析验证不回贴；用错误 Key 验证 401 不无限重试。

### P3-R04 两阶段索引与新鲜度

- 阶段一（同步，预算 ≤3s P95）：缩略图 ≤150ms → OCR 300–1500ms（文本素材跳过）→ 临时嵌入 <30ms → **同事务**写 `insights` + `items_fts` + 向量表。完成后素材即被三路检索命中，`status` 保持 `parsing`，发 `item_indexed` 事件。
- 阶段二（异步）：VLM 返回后更新摘要/标签/结构化属性 → 递增 revision → 重建嵌入与 FTS → `status='ready'`，发 `item_enriched`。
- **同事务原则**：insights、FTS、向量三处写入在同一 SQLite 事务内；任一步失败整条回滚，任务重试。
- 阶段二失败不影响可检索性（阶段一数据仍在）。

**验收方法**：连续捕获 10 张截图，逐条记录提交→`search_items` 可命中的耗时取 P95；构造向量写入失败（改表结构模拟）验证回滚后重试无半更新；杀进程在阶段二中间重启验证恢复。

### P3-R05 全文通道（中文 FTS）

- jieba 预分词 + FTS5 `unicode61 remove_diacritics 2`：写入侧与查询侧用同一分词器与同一版本（`fts.tokenizer_version` 记录于库）。
- 索引列：`title, summary, ocr_text, note, tags, entities, original_text`；`items_fts` 为 contentful 表，rowid 与 `items.rowid` 对齐。
- 文本素材原文全量进 FTS（片段 ≤10000 字符、文件 ≤500KB 不截断）。
- BM25 排序，`snippet()` 生成命中摘要（自动选最佳列）；不引入自定义 SQLite 分词器、不引入外部搜索引擎。
- 删除素材时 FTS 行在同一删除事务内清理。

**验收方法**：20 条素材上用 10 条真实中文查询（含 2 字词、4 字词、专有名词、报错码）验证字面召回与 snippet；中英混排、全角符号、emoji 查询不崩溃；删除素材后 FTS 计数减少。

### P3-R06 查询解析与 chip 回显

- 纯本地规则解析（零网络、零大模型），输出 `ParsedQuery`：`time/app/color/chart/contentType/hasFormula/tags` 过滤器 + `semanticText` + `lexicalTerms`；解析确定性可用 proptest 回归。
- 支持的规则：闭集词表（时间：今天/昨天/前天/本周/上周/本月/上个月/今年/最近 N 天；颜色：红橙黄绿蓝紫粉棕黑白灰/深色/浅色，同义词表归一到标准色枚举；图表：柱状/折线/饼/漏斗/表格；类型：截图/文本/链接；「公式」→ hasFormula）＋ 显式键值语法（`app:Chrome`、`tag:工作`、`color:橙`）＋「来自 X / 在 X 里」应用名模式 ＋ 双引号内容（引号内分词后全部词为必命中项）。
- chip 回显每个已识别过滤器（含来源标签），点击 × 删除并重算；剩余未识别文本作为语义与字面查询词。
- 查询解析耗时 ≤5ms。

**验收方法**：每条规则给正例与反例各一（如「上个月」命中而「上个」不误命中时间）；删除时间 chip 后同一查询不再带时间过滤；显式语法与自然语言混输。

### P3-R07 三路召回与 RRF 融合

- 三路：结构化过滤（SQL）+ FTS BM25 + 语义向量；无 CLIP 图向量通道（不做图搜图，含二期）。
- 融合：应用层 RRF，`score = Σ wᵢ/(k + rankᵢ)`，k=60；权重（FTS/语义）写入 `settings` 可配置，默认 1.0/1.0，由评测集校准。
- FTS 与向量各取 Top-200 进入融合；平局按 `captured_at DESC`。
- 仅过滤命中（字面与语义都未命中）的素材附加在融合结果之后，解释为 filters-only，不与文本得分混排。
- 嵌入未就绪时语义通道跳过，结果照常返回（降级标注，见 P3-R13）。
- 检索延迟 ≤800ms（P95，测试规模内）；预算分解见 design §6.3。
- `failed` 素材可被 OCR 命中，卡片明示状态。
- 每次检索写一行 `queries` 记录（raw/parsed/结果 id 列表），供评测与反馈闭环；不提供历史 UI。

**验收方法**：构造覆盖三通道各自的必命中查询各 3 条；改 RRF 权重验证排序变化可复现；空库/无结果返回空态而非报错；`took_ms` 记录在响应中并可采样 P95。

### P3-R08 命中解释与 OCR 高亮

- 每条命中携带 `Explanation`：`filters`（实际命中的结构化条件）、`terms`（FTS 实际命中词）、`semantic`（是否仅语义命中）、`highlightBoxes`（OCR 命中词对应的归一化包围盒）。
- 解释只来自实际命中的索引项：filters 只列该素材属性真正匹配的条件；纯语义命中显示「语义相关」，不编造词。
- OCR 命中词经 `ocr_boxes_json` 映射为预览图高亮框；映射失败（词跨框/框缺失）退化为文字高亮，不报错。

**验收方法**：三类命中（纯过滤、字面、语义）各验一条，解释内容与索引事实一致；搜图上某段文字验证高亮框落在对应位置；删除 boxes 数据验证退化路径。

### P3-R09 搜索界面

- `SearchBar`：位于列表区顶部；输入防抖 250ms；请求带序号，过期响应（后发先至）被丢弃；清空回到默认列表模式。
- `QueryChips`：解析结果回显（P3-R06），chip 可删。
- `ResultGrid`：复用既有卡片网格；卡片显示命中徽标（命中词/语义/筛选）与 AI 摘要首行；空结果有引导态（「没有找到，试试更短的关键词」）。
- `ExplainBar`：选中结果时展示命中解释；图片素材提供「在图中高亮」开关，在详情预览上叠加 OCR 高亮框。
- 详情面板摘要区接真实数据：摘要 + 来源徽标（AI 摘要 / OCR 摘录 / 无）；复制按钮启用；自动标签带「自动」角标（复用阶段 02 chip 视觉）。
- 状态栏：后台索引队列水位（`pipeline_status`）；语义通道降级标注。

**验收方法**：连续快速输入验证防抖与过期丢弃；空查询不发起检索；三类命中的徽标与解释正确；OCR 高亮开关前后视觉对比；摘要来源徽标与 `summary_source` 一致。

### P3-R10 标签云筛选与 hue-dot（阶段 02 遗留收口）

- 侧栏标签 pill 可点击：点击后作为 tag 过滤 chip 进入搜索上下文，列表按该标签筛选；再次点击或删除 chip 取消。
- 卡片 hue-dot：`insights.primary_color` 非空时显示主色圆点（归一化色枚举 → 前端固定色板），为空不显示。
- `list_items` / `get_item` / 搜索命中返回 `primaryColor`（LEFT JOIN insights，可能为 null）。

**验收方法**：点标签筛选→删除 chip 恢复；有/无 `primary_color` 的卡片圆点表现；颜色词搜索与圆点口径一致（搜「橙色」命中的素材圆点为橙）。

### P3-R11 模型配置（F7.1）

- 设置新增「模型」pane：主/备两组配置（base URL、模型名、API Key），API Key 写入 Windows 凭据管理器（`keyring`），界面只显示「已设置/未设置」，**任何 IPC 不回传明文**。
- 「探测」按钮：连通性（文本 ping）+ 视觉能力（最小图片请求）+ 延迟，结果行内展示；探测在后端执行。
- 保存即生效（Provider 注册表热更新），无需重启。
- 主备切换：请求失败（网络/5xx/超时）自动切备；恢复后切回主（下一轮任务）。
- 密钥错误（401/403）：明示配置错误，不无限重试（P3-R03）。
- 嵌入/OCR 模型为本地内置，不在该 pane 配置；`embedding_rebuild` 管理命令（无 UI）供评测/升级流程触发向量蓝绿重建。

**验收方法**：配主备两组真实配置，断主验证切备与恢复；错误 Key 验证 401 终止与提示；检查凭据管理器条目存在、界面与 IPC 响应中无明文；改 base URL 保存后立即生效。

### P3-R12 索引生命周期

- revision 幂等：`items.revision` 为真相来源；note/标签/摘要变更 `bump_revision` 并合并入队 `index` 任务；claim 时 revision 不匹配的旧任务标记 `cancelled`，同一素材只保留最新任务。
- 模型固定于库：`embedding.model_id/dim` 首次写入后变更必须走蓝绿重建，直接混写返回错误。
- 蓝绿重建：新建向量表 → 后台全量重嵌入 → 行数校验 → 原子切 `vector.active_table` 指针 → 旧表保留回滚；重建期间检索零中断。
- 删除清理：单条/全库删除事务内清 insights（FK 级联）、向量（FK 级联）、FTS（显式 DELETE）。
- insight 复用：相同 `content_hash` 的截图复用已生成的 insight（省 VLM 调用；不改变「不去重」的产品行为）。
- 启动自检：`items`/`items_fts`/活跃向量表行数比对，缺失派生数据自动入队修复（P0 计数+日志，修复入队随 pipeline 落地）。

**验收方法**：连续改备注 3 次验证只有一个待执行 index 任务且旧任务被取消；人为删除一条 FTS 行重启后自动修复；触发蓝绿重建全程可检索、完成后行数一致；同 hash 二次捕获不产生第二次 VLM 调用（日志计数）。

### P3-R13 任务队列与降级可见性

- 复用既有 `jobs` 表：2 worker、指数退避 2/5/15s、单任务尝试上限 3；崩溃恢复 `running→queued`（既有逻辑保留）。
- 任务阶段：`ocr`（仅图片）、`index`（嵌入+FTS 同事务写）、`vlm`、`rebuild`；优先级 新捕获 > 重试 > 全量重建。
- 降级矩阵全部 **UI 可见**（失败不静默）：

| 场景 | 行为 | UI |
|---|---|---|
| 无网络/无 Key | 捕获+OCR+临时嵌入可用；VLM 排队，OCR 摘录占位 | 摘要区「OCR 摘录」徽标 |
| 嵌入模型未就绪 | 检索退化 FTS+过滤 | 状态栏「语义检索未就绪」 |
| OCR 无文字（空结果或两级引擎都失败） | insights 建行，ocr 字段 NULL/空，不写占位摘要，index/vlm 照常 | 标题回退窗口标题/时间，状态「待解析」标注，不触发「置信度低」 |
| 主 Provider 失败 | 切备；都失败按退避重试 | 队列状态/错误事件 |
| 401/403 | 终止重试 | 设置 pane 与 Toast「配置错误」 |

**验收方法**：断网全流程走一遍核对矩阵每行；强杀进程在任务执行中重启验证恢复；两个 worker 并发下无重复执行（job 状态断言）。

### P3-R14 检索质量评测

- 50 条真实中文查询评测集（人工标注相关素材，私有文件不入库分发；格式模板入库 `docs/eval/`）。
- 指标：Top-3 命中率（Top-3 含至少一条相关素材的查询占比）、Recall@10、mAP、P95 延迟、命中通道分布（FTS/语义/仅过滤）。
- 分桶：截图类（OCR 主导）/ 场景类（语义主导）/ 字面类（编号/报错），验证各通道各司其职。
- **门禁：Top-3 命中率 ≥80% 为阶段 03 退出条件。**
- 调参回路：RRF 权重、jieba 词典、search document 字段顺序、颜色同义词表——每次变更必跑评测并存档对比（报告入 `docs/eval/`）。
- 不达标回退顺序：调 jieba 词典/分词策略 → 调 RRF 权重 → 升级 bge-base-zh-v1.5（蓝绿重建）→ 加同义词层；每步以评测数据为依据。
- 反馈数据：`queries` 表记录检索与「不是这个」反馈（IPC `search_feedback`，UI 入口为 P1），持续扩充评测集。

**验收方法**：`cargo run -p visrecall-eval` 产出报告；门禁数字与分桶报告存档；至少一轮「变更→评测→对比」记录（如权重调整）。

### P3-R15 构建、绑定与类型一致性

- `cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace` 全绿。
- `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 全绿。
- `tauri-specta` 生成的 `src/lib/bindings.ts` 与 Rust 定义一致；release 二进制可脱离 dev server 运行（沿用阶段 02 配置）。
- 新增依赖全部锁定 `Cargo.lock`/`pnpm-lock.yaml`；不引入：向量数据库客户端、HTTP 嵌入服务、ES/Meilisearch、PyTorch 系运行时。

**验收方法**：跑全部命令记录耗时；`git diff` 确认绑定文件与 Rust 同步；`Cargo.toml` 依赖清单与 design 附录一致。

## 4. 明确不做（阶段 03）

- **CLIP 图向量 / 图搜图（含二期）**：不做通道、不做 schema 预留；无字图片靠 VLM 摘要参与语义检索（架构文档 2026-11-08 决策）。

- **`sqlite-vec` vec0 快路径**：主路径为 int8 暴力余弦；vec0 仅 T0 spike 验证编译与一致性，不进迁移 0003，不作为功能依赖。

- **搜索历史 UI**（F3.7）：`queries` 表只作评测与反馈数据。
- **相似推荐（P2）**、视频、语音。
- **数据流向页**（F6.3，阶段 04）、安装包/签名/自动更新/开机自启（阶段 04）。

- **嵌入模型空闲卸载**：懒加载+预热必做；按空闲时间卸载留给阶段 04 内存优化统一处理（偏差已登记 design §1.2）。

## 5. 阶段退出条件
