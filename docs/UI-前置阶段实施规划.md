# UI 前置阶段实施规划（阶段 02 启动前）

> 日期：2026-11-06  
> 背景：阶段 02 spec 已删除待重写。UI 实施先行，作为独立前置阶段执行；产出一套符合原型视觉的完整界面骨架，以及一份**前后端接口契约草案**，作为重写阶段 02 spec 的直接输入。  
> 依据：`docs/prototype/index.html`（视觉与交互规范）、`docs/specs/v0.1/README.md` §2（V0.1 功能范围基线）。  
> 状态：待评审。决策点 D-UI-1 ~ D-UI-4 均已定稿（2026-11-06，见 §8），T1 直接进入实施。

## 1. 定位与原则

1. **只动前端（`src/`），不改 Rust 行为**。后端沿用阶段 01 既有命令与事件；不存在的后端能力一律走 stub 层。
2. **stub 不做假**：stub 返回明确占位（如详情面板 AI 描述固定「待解析（阶段 03 提供）」），不留"看起来能用其实是假数据"的暗桩；stub 边界以注释与统一出口标记，新 spec 落地后逐个替换。
3. 原型定视觉与交互，范围基线取 README §2 的 V0.1 功能映射表；原型中 V0.1 范围外的元素不进 DOM（见 §7 裁剪清单）。
4. 顺序：地基 → 骨架 → 组件；组件按可接真实后端的程度排序，能接的先接，减少 stub 面积。

## 2. 后端现状盘点（决定 UI 分工）

**可直接接（阶段 01 已有，无 stub）：**

| 能力                             | 来源                  | 对应 UI           |
| ------------------------------ | ------------------- | --------------- |
| `commands.getAppStatus()`      | 阶段 01               | 状态栏 / 库状态       |
| `commands.listItems()` 分页 + 去重 | 阶段 01（现 App.tsx 已用） | 素材网格、`加载更多`     |
| `commands.openLibraryFolder()` | 阶段 01               | 设置存储 pane「打开」按钮 |
| `subscribeItemEvents()`        | 阶段 01               | 列表自动刷新          |

**必须 stub（新 spec 的契约对象）：**

| 能力                                                            | 对应 UI             | 契约要点（写入契约草案）                                                             |
| ------------------------------------------------------------- | ----------------- | ------------------------------------------------------------------------ |
| 详情读取（图片 `visrecall://original/<id>` / 文本原文前 2 万字符 / 链接标题+URL） | 详情面板              | 按 id 读取、返回类型判别联合                                                         |
| 备注读写（300ms 防抖、10000 字上限）                                      | 详情面板              | `note_get/note_set` + `item_note_updated { id }`                         |
| 标签增删改名（chip、自动「A」角标/手动实色、同名复用）                                | 详情面板              | `tags_*` 命令 + `item_tags_updated` / `tags_changed`；`tag_suppressions` 语义 |
| 原始内容复制（CF_DIB+PNG / CF_UNICODETEXT）                           | 详情面板操作区           | 按类型三命令 + `CLIPBOARD_BUSY/FAILED`、`FILE_MISSING`                          |
| 单条/全库彻底删除                                                     | 详情面板 + 设置         | `item_delete` + 确认对话框文案数据源                                               |
| 存储用量/容量/保留策略/位置迁移                                             | 侧栏存储条 + 设置存储 pane | 用量查询、容量与保留天数设置、迁移进度事件                                                    |
| 悬浮球显示设置（40/48/56、贴边收起）                                        | 设置捕获 pane         | 配置读写；本体是 Rust 侧窗口，UI 只出控件                                                |
| AI 描述                                                         | 详情面板占位            | 阶段 03 接入，契约预留 `SUMMARY_UNAVAILABLE`                                      |

stub 层设计：`src/lib/api.ts` 作为唯一出口，stub 与真实命令**同签名同返回类型**；阶段 02 重写 spec 后按契约逐个换成 `commands.*` 调用，UI 组件零改动。

## 3. 交付物（DoD）

1. `tokens.css`：原型令牌体系 + 明暗双主题 + 切换持久化。
2. 布局骨架：自定义标题栏（D-UI-1 已定 B）+ 三栏 workspace + 状态栏；现有网格/空态迁入。
3. 素材卡片视觉升级对齐原型（时间、缩略图、hue-dot 预留接口；徽标保留现有 pending 简化版）。
4. 详情面板 UI 完整（stub 数据驱动，交互细节完整：防抖保存、Esc flush、字数上限阻止）。
5. 设置弹窗（捕获 / 存储两个 pane，stub）+ 确认对话框组件。
6. 侧栏（视图组 + 标签云 stub + 存储条 stub）+ 折叠交互。
7. 全局件：Toast、空态、键盘（Esc / T / B；`Ctrl K` 预留不激活）。
8. `docs/specs/v0.1/ui-contract-draft.md`：上表契约写成命令/事件/类型草案（TS 类型为主，标注对应 `visrecall_domain` 类型方向），供新 spec 直接引用。
9. `pnpm lint / typecheck / test / build` 全绿；现有 role/text 测试零回归；新增组件测试随任务写。

## 4. 任务序列

```
T1 决策定稿 + tokens + 主题机制
T2 布局骨架 + 自定义标题栏（decorations:false，见 D-UI-1），现有网格迁入
T3 卡片视觉升级（接真实 listItems）
T4 详情面板（stub）+ 查看原图（应用内 overlay，D-UI-4 已定）
T5 设置弹窗（stub）+ 确认对话框
T6 侧栏 + 折叠（存储条 stub；标签云在 T4 标签类型定稿后接 stub）
T7 全局件（Toast/空态/键盘）
T8 契约草案文档 + 视觉验收（双主题、原型逐屏对照、100 条滚动）
```

依赖关系：T1 → T2 是一切的前置；T4–T6 依赖 T2 骨架但彼此独立可并行；T8 收尾。能接真实后端的只有 T3（及设置里「打开库目录」一处），其余组件开发时即按契约面向接口写，不感知 stub。

## 5. 验收清单

- **原型逐屏对照**：自定义 titlebar / 侧栏 / 主栏 / 详情栏 / 设置弹窗 / Toast / 空态，逐屏核对布局、间距、字号、明暗两套配色。
- **自定义标题栏专项**：拖拽移动、双击最大化/还原、窗口按钮（min/max/close）、缩放边缘 resize、多屏拖拽跨屏；Win10 与 Win11 各验一轮（Win10 无系统圆角，确认方角观感可接受）。
- **双主题对比度**：明暗两套全部界面过一遍，正文/次要文字/边框对比度可读。
- **滚动与翻页**：100 条以内滚动流畅、`加载更多` 反复翻页（阶段 01 遗留门禁项在此环境先测一轮，结论供新 spec 引用）。
- **交互红线**：AI 描述只显示「待解析」占位；所有可交互元素要么接真实命令、要么走 stub 占位，不存在死按钮。
- **无范围蔓延**：§7 裁剪清单内元素不实现；若想保留，先在新 spec 里立项再动代码。

## 8. 决策点（已定稿 2026-11-06）

| ID     | 事项    | 选项                                        | 结论                                                                                                                                        |
| ------ | ----- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| D-UI-1 | 标题栏形态 | A 系统标题栏；B `decorations:false` 自定义         | **B（已定，2026-11-06）**：原型 titlebar 承载品牌区、库状态与主题/设置入口，属信息架构而非装饰，A/C（Win11 染色标题栏，仅覆盖 Win11）都无法承载；提前到 T2 实现，不再排阶段 04。唯一可见妥协是 Win10 无系统圆角（窗口方角） |
| D-UI-2 | 默认主题  | A 跟随系统；B 固定暗色                             | **A**：默认跟随系统 `prefers-color-scheme`，手动切换后持久化用户选择                                                                                          |
| D-UI-3 | 字体    | A 系统字体栈回退；B 打包 Inter/JetBrains Mono woff2 | **A**：系统字体栈（`Segoe UI` / `Cascadia Mono` 等），不打字体包；视觉验收不满意再升 B                                                                             |
| D-UI-4 | 查看原图  | A 调系统默认程序；B 应用内 overlay                   | **B**：应用内 overlay，随 T4 一并实现                                                                                                               |

D-UI-1 实现要点（T2 执行）：`tauri.conf.json` 窗口配置 `"decorations": false, "shadow": true, "resizable": true` 并设 `minWidth/minHeight`；titlebar 容器加 `data-tauri-drag-region`（内部按钮不加，否则拦截点击）；min/max/close 调 `getCurrentWindow()` 对应 API；双击最大化由 drag-region 自动处理；Snap Layouts 悬停弹窗在自定义标题栏下不可用，接受降级为普通最大化。
