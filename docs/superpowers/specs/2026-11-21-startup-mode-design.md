# VisRecall 启动方式设计：静默启动 / 启动时显示主窗口

> 日期：2026-11-21
>
> 状态：已实现；自动化验证通过，Windows 实机验收待用户执行。

## 1. 背景与目标

VisRecall 当前冷启动时只驻留托盘，不创建前端主窗口和 WebView2；点击托盘或再次运行应用才会打开主窗口。这个行为适合常驻捕获，也有用户希望首次运行时直接进入素材库。新功能让用户自行选择：**完整启动一个新进程时，是否自动打开主窗口**。

- **静默启动（默认）**：驻留系统托盘，不创建主窗口或它的 WebView2。热键、原生悬浮球和索引任务按各自配置及现有可用性正常运行；静默不等于关闭悬浮球、禁用通知或暂停后台任务。
- **启动时显示主窗口**：正常初始化后台服务和托盘，随后自动打开现有的主窗口，效果与从托盘打开一致。

本期不增加 Windows 登录自启动、命令行覆盖参数、每次启动弹窗或首次启动向导，也不改变捕获流程和关闭窗口后的常驻行为。「是否随 Windows 登录运行」与「运行时是否显示窗口」是两个独立问题。

## 2. 方案选择

| 方案 | 优点 | 代价与取舍 |
| --- | --- | --- |
| **设置中保存偏好（推荐）** | 设置一次、后续生效；兼容现有用户与低内存启动策略 | 想更改时先通过托盘唤醒主窗口，再进入设置 |
| 每次启动弹窗询问 | 每次都能临时决定 | 静默启动前仍要出现提示；无法无人值守启动 |
| 通过不同快捷方式或参数选择 | 支持按启动入口临时切换 | 需要管理快捷方式和参数，不适合作为普通用户的唯一入口；本期不做 |

首次安装和旧版升级都沿用「静默启动」。不根据上一次退出时主窗口是否可见推断偏好。

## 3. 用户交互与行为规则

入口：**主窗口 → 设置 → 通用 → 启动方式**。新增「通用」分区，保留现有设置默认打开的分区。用有明确标签的两项单选控件，支持键盘操作：

| 选项 | 说明文案 |
| --- | --- |
| 静默启动 | 启动后驻留系统托盘。点击托盘图标可打开主窗口。 |
| 启动时显示主窗口 | 启动后自动打开主窗口，后台功能照常运行。 |

控件下方提示：「下次启动生效。关闭主窗口不会退出应用；如需立即验证，请从托盘退出后重新启动。」修改即保存，不弹出重启确认，不关闭或打开当前窗口。读取设置时不展示可操作的假默认值；保存期间禁用该控件，成功后回填新值，失败则保留上次确认值并提示错误；读取失败时提供重试。

| 用户操作 / 场景 | 预期行为 |
| --- | --- |
| 应用未运行，从开始菜单、快捷方式或可执行文件启动 | 按已保存的启动方式决定是否自动打开主窗口。 |
| 应用正在运行，再次启动 | 现有进程始终响应显式唤醒，不受静默偏好限制；已有窗口则恢复并聚焦，窗口已销毁则重建，不新增长期驻留进程或第二个主窗口。 |
| 点击托盘图标或托盘菜单「打开主窗口」 | 始终允许打开，不受启动方式限制。 |
| 关闭主窗口 | 与现有行为一致：先隐藏；若未再唤醒，约 60 秒后销毁窗口和 WebView；应用仍驻留托盘。 |
| 库迁移后点击「立即重启」 | 新进程按已保存的方式启动。迁移横幅补充提示：「若设置为静默启动，重启后可从托盘打开主窗口。」 |
| 托盘退出后再次启动 | 读取磁盘配置，应用最新成功保存的偏好。 |

## 4. 技术设计

### 4.1 偏好归属与兼容

- 该设置属于应用而非素材库，存放在现有 `config.json` 中（通常为 `%APPDATA%\VisRecall\config.json`），不新增 SQLite 字段或配置文件；库路径迁移不得重置它，库不可用时也不妨碍读写此偏好。
- 在 `crates/library/src/config.rs` 的 `AppConfig` 新增 `startup_mode`，Rust 类型建议为 `StartupMode`；磁盘及 IPC 枚举值统一为 `silent`、`show_window`。IPC 字段遵循 `startupMode`，与磁盘键 `startup_mode` 区分。
- 文件不存在或旧配置缺少字段时默认 `silent`，不要求启动时补写。若 JSON 整体有效但该字段的值未知或类型错误，仅该字段回落到 `silent` 并记录告警，保留库路径、热键等其它字段。整个文件无法解析或读取时沿用现有全局回退；损坏文件继续走现有备份逻辑。
- 复用 `AppCore::update_settings` 和 `AppConfig::save_atomic`。同一次配置加锁内完成读取旧值、合并补丁、原子落盘和更新内存；保存失败不更新内存。修改启动方式不触发热键重注册、悬浮球重配或索引重启。

### 4.2 启动决策与窗口生命周期

1. `src-tauri/src/main.rs` 保留 DPI 第一条语句、单实例插件优先注册，以及现有核心、托盘和后台服务初始化顺序。`AppCore` 打开配置后，启动流程从同一份已加载配置取得启动方式，不在 Tauri 层再次读取磁盘。
2. 完成 `AppCore` 托管、托盘创建、窗口生命周期接线和现有后台启动动作后，再消费**一次**冷启动决策。`silent` 不调用窗口创建入口；`show_window` 走 `window_lifecycle::show_main_window`，复用现有投递到主线程、查找/创建、唤醒和销毁代号失效逻辑。无需等待 OCR 或索引任务实际处理完毕才打开窗口。
3. 不在 `tauri.conf.json` 静态声明主窗口，也不先创建后隐藏。React 不负责启动决策。单实例回调、托盘唤醒、捕获前后隐藏/恢复、关闭后的延迟销毁继续走既有机制，不再按启动偏好分支。冷启动和显式唤醒若相邻到达，仍通过同一个串行窗口入口，不重复创建。
4. 主窗口创建或派发失败只记日志，不撤销托盘和已启动的后台服务，也不改写偏好；用户可从托盘重试。库打不开时保留现有异常托盘：静默模式不强制弹窗，显示模式仍尝试打开主窗口，用现有错误状态提示库不可用。托盘本身创建失败则沿用现有启动失败处理，不允许新增「无托盘、无窗口却常驻」状态。

### 4.3 设置接线与涉及文件

| 位置 | 设计职责 |
| --- | --- |
| `crates/library/src/config.rs` | 定义启动方式、默认值与旧配置兼容策略。 |
| `crates/app-core/src/app.rs`、`crates/app-core/src/lib.rs` | 扩展 `SettingsPatchInput`，复用应用配置的原子持久化路径；按需重导出领域类型给 Tauri 层。 |
| `src-tauri/src/main.rs`、`src-tauri/src/window_lifecycle.rs` | 前者负责冷启动决策；后者继续是唯一主窗口入口，不新增第二套生命周期。 |
| `src-tauri/src/ipc.rs` | 扩展现有 `SettingsDto` 和 `SettingsPatch`，继续使用 `get_settings` / `update_settings`。未传 `startupMode` 的补丁保持原值，来自 IPC 的非法枚举值应拒绝，不按磁盘兼容规则默默回退。 |
| `src/lib/api.ts`、`src/lib/bindings.ts` | 复用现有 `api` 调用和 `queryKeys.settings`；由 tauri-specta 重新生成绑定，禁止手改。无新增 IPC 命令、事件或查询键。 |
| `src/features/settings/SettingsDialog.tsx`、`src/app/App.tsx` | 设置弹窗新增「通用」及启动方式控件，复用设置查询和保存回填流程；应用层仅补迁移重启提示，不参与窗口决策。 |

## 5. 验收与验证

**自动化验证（实施后执行）**

- Rust：覆盖旧配置无字段、两种合法值的往返、坏字段不影响自定义库路径、损坏文件整体回退；覆盖补丁未传时保留偏好、成功后新进程可读回，以及落盘失败时配置不切换。前端 DTO 的枚举值和可选补丁由绑定一致性测试校验。
- 前端：覆盖已存偏好的正确选中、切换只提交 `startupMode`、保存期间禁用、失败保留原值并提示、加载失败可重试。验证命令：`pnpm typecheck`、`pnpm lint`、`pnpm test`；Rust 运行 `cargo test --workspace`。

**Windows 实机验收（实施后执行）**

1. 从托盘完全退出，以静默模式启动：托盘出现，无主窗口或任务栏窗口，不创建该实例的主窗口 WebView2；在启用时验证悬浮球和捕获热键仍正常。检查 WebView2 时只看与 VisRecall 关联的进程，不误算其它应用的进程。
2. 从托盘打开窗口，切换到「启动时显示主窗口」：当前窗口保持原样；从托盘退出并重新运行，托盘和主窗口均出现，只出现一个主窗口。改回静默后重复验证。
3. 静默启动后再次运行程序，确认已有实例打开窗口；分别在关闭后 60 秒内和超时后验证窗体复用、销毁后重建，以及前一次关闭的计时器不会销毁已重新唤醒的窗口。
4. 使用临时测试配置模拟库不可用，验证静默模式保留异常托盘且能手动唤醒，显示模式进入现有错误状态。验证库迁移后的「立即重启」遵循已保存偏好，静默时仍可从托盘打开并看到迁移后的库。
5. 区分托盘就绪与主窗口可见两个时间点，分别记录冷启动指标。静默路径不因本功能引入 WebView2 初始化成本；显示路径不要求等索引任务完成。

实施记录见[启动方式实施计划](../plans/2026-11-21-startup-mode.md)。技术架构文档的启动、窗口生命周期和配置章节已同步。
