# VisRecall 主界面上传入口与目录引用导入方案

> 日期：2026-11-10  
> 状态：已确认搜索框右侧入口与统一弹窗方向；本次仅更新方案，尚未实现。  
> 范围：主界面添加图片、TXT/Markdown 文件、文字入口，以及不复制原文件的目录导入。  
> 原则：保留悬浮球；复用已有素材库与检索管线；目录默认只建立引用；不自动提交 Git。

## 1. 结论与推荐方案

建议采用 **“统一添加入口 + 文件复制入库 + 目录引用索引”**：

1. 在主界面搜索框右侧增加常驻的 **“＋ 添加”** 按钮，与搜索框等高，放在输入容器外侧。
2. 点击打开统一的 **“添加素材”弹窗**，支持拖拽文件、选择文件、选择目录，并保留“新建文字”次级入口；不再采用结果标题栏下拉菜单。
3. 图片和 TXT/Markdown 文件选择导入默认由应用保存副本；图片沿用现有标准化处理，文本沿用现有解码与保存逻辑。手动输入的文字保存到素材库。
4. 目录导入默认 **不复制原文件、不创建系统级软链接**，而是在数据库登记目录和相对路径，由后端按需读取。
5. 目录内的原文件始终只读。删除素材、清空库、容量清理、迁移库，都不得修改或删除引用目录里的原文件。
6. 仅规划两个阶段：第一阶段打通现有图片、TXT、Markdown 和文字入口；第二阶段完成目录引用。保持现有素材类型，不新增独立文档类型或专用文档解析能力。

这里的“引用索引”相当于应用层软链接，达到“不再保存一份原文件”的目标，但不依赖系统软链接权限。它不是磁盘备份：外部目录不可用时，原文件也不可用。

**明确假设：** 以当前 Windows 桌面应用和本地目录为首发场景；首版目录更新采用手动刷新，不默认后台持续监控；“上传”在界面上表述为“添加 / 导入”，不等于发送到云端。

## 2. 现状核查

本节依据当前仓库实现，不把产品设想当作已完成功能。

| 位置 | 当前情况 | 对方案的影响 |
| --- | --- | --- |
| `src/app/App.tsx` | 已有面包屑、搜索框、结果标题行；没有主界面导入按钮 | 用搜索操作行包裹 `SearchBar` 与右侧添加按钮，不改动窗口标题栏和搜索内部操作 |
| `src/features/library/EmptyState.tsx` | 仅提示快捷键捕获、悬浮球捕获和拖拽图片 | 增加可点击的导入引导 |
| `crates/app-core/src/import_flow.rs` | 支持 PNG/JPG/JPEG/WebP/GIF、TXT/MD、文字片段、链接和位图；明确拒绝文件夹 | 复用单项处理能力，新增目录枚举和任务编排 |
| 同上 | 拖放最多 20 个文件；图片 20 MiB；文本文件 500 KiB；文字片段 10,000 字符 | 目录不能简单展平后塞入一次拖放 |
| 同上 | 图片转为 PNG，长边超过 8,000 时缩小；文本文件解码后保存 | 引用导入不得调用落盘原图副本的路径；已有编码兼容能力应复用 |
| `crates/domain/src/item.rs`、`crates/library/migrations/0001_core.sql` | `ItemKind` 仅有 `image/text/link`；`original_path` 约定为库内相对路径 | 保持素材类型不变，仅扩展存储归属、来源模型和显示状态 |
| `src-tauri/src/ipc.rs`、`src-tauri/src/main.rs` | 已注册 dialog 插件，有 Rust 侧 `pick_directory` | 文件选择器继续放在 Rust 侧 |
| `src/lib/bindings.ts` | Tauri Specta 生成的命令与类型 | 新增命令应重新生成，不手改生成文件 |
| `crates/app-core/src/thumbnail.rs`、`crates/app-core/src/detail.rs` | 缩略图、原图、文字预览依赖库内路径 | 引入统一资产读取服务，不把绝对路径塞进 `original_path` |
| `crates/pipeline/src/handlers/mod.rs` | OCR、索引等共用库内读取；文字参与索引目前截取到 10,000 字符 | 引用图文接入既有管线，保留现有文字索引上限并明确提示 |
| `src-tauri/src/protocol.rs` | `visrecall://` 按素材 ID 提供库内图片，采用不可变缓存 | 引用文件变更后要按版本刷新，不能放开任意路径读取 |
| `crates/library/src/cleanup.rs` 等 | 清理、用量、删除、迁移各有库内文件逻辑 | 必须整体检查所有权边界，不只实现导入后能显示 |

## 3. 方案比较：是否直接使用系统软链接

| 方案 | 原文件额外占用 | 优点 | 主要问题 | 建议 |
| --- | --- | --- | --- | --- |
| A. 全量复制目录 | 高 | 原文件删除后仍可使用；备份和迁移直观 | 违背减少占用目标；大目录导入慢 | 不作为目录默认方案 |
| B. 库内建立系统软链接 / Junction | 通常不复制原文件 | 路径形式接近普通文件 | 平台、权限、断链、重解析点、清理和备份工具差异 | 首版不采用 |
| C. 数据库记录目录与文件引用 | 仅索引及派生缓存 | 无需创建系统链接；来源、失效和迁移语义清楚 | 需要统一读路径，新增来源状态管理 | **推荐** |

Windows 创建符号链接涉及对应权限；无特权创建也受 API 标志和开发者模式等条件影响。因此不应要求用户以管理员身份运行，只为了导入目录。Junction 与文件软链接也不是完全相同的能力。[R1][R2]

不建议用硬链接替代：它不等于指向外部路径的目录引用，文件修改仍共享数据，且不能作为任意目录、任意卷的通用方案。[R2]

**决策：** 首版实现 C。除非将来出现明确的外部工具兼容需求，否则不增加“系统软链接模式”开关，避免两套几乎相同的入口和生命周期。

## 4. 界面与交互设计

### 4.1 常驻入口

保持现有配色、设计令牌、系统字体、圆角与明暗主题，不重新设计应用外壳。

```text
素材库 / 全部素材
┌───────────────── 搜索素材 ─────────────────┐  [＋ 添加]
└───────────────────────────────────────────┘
全部素材  128 项

┌──────────┐  ┌──────────┐  ┌──────────┐
│ 素材卡片 │  │ 素材卡片 │  │ 素材卡片 │
└──────────┘  └──────────┘  └──────────┘
```

- 入口在普通列表、搜索结果和侧栏折叠时都存在；不能只有空库时才可导入。
- 搜索框自适应占据剩余宽度，添加按钮保持固定宽度与等高；不放进搜索输入容器，避免挤占清空按钮、快捷键提示和搜索状态。窄窗口可收为带可访问名称的加号按钮。
- 空库提供“添加素材”按钮，打开同一个弹窗，同时保留截图和悬浮球提示，不建设第二套导入界面。
- 搜索中导入不清空查询；新素材不匹配当前条件时，提示“已添加，查看全部素材”。
- 文件选择器仅展示支持的图片及 TXT/MD 扩展名；其他类型不提供导入入口。
- 本轮不新增全局快捷键，避免与已有截图、主题、侧栏及输入操作冲突。
- 弹窗内拖拽文件是阶段一交付内容；弹窗之外的主窗口任意区域拖放才是后续增强，不影响既有悬浮球拖放。

### 4.2 统一“添加素材”弹窗

```text
┌─────────────────────────────────────────────┐
│ 添加素材                                  × │
│ 将图片、文本文件或本地目录添加到素材库        │
│                                             │
│  ┌───────────────────────────────────────┐  │
│  │                                       │  │
│  │             拖拽文件到这里             │  │
│  │        支持图片、TXT、Markdown          │  │
│  │                                       │  │
│  └───────────────────────────────────────┘  │
│                                             │
│  [ 选择文件 ]          [ 导入目录 ]          │
│  保存到素材库          引用原文件，不复制    │
│                                             │
│  也可以：新建文字                           │
└─────────────────────────────────────────────┘
```

- 使用“添加 / 导入”，不把本地复制与目录引用统称为“上传”；是否调用云端 AI 另按来源授权及全局隐私设置判断。
- 弹窗建议宽约 600px，最大宽度与高度受当前窗口约束；内容过长时内部滚动，底部操作始终可达。沿用暖白底色、细边框、圆角、现有字体与明暗主题，不另起渐变主题。
- 拖拽区采用淡色虚线边框、简洁线性图标；有效拖入时轻微高亮并提示松开添加，不支持内容有明确提示，不只靠颜色区分。减少动画设置下取消非必要动效。
- “选择文件”为主操作，“导入目录”为次操作，分别展示保存副本与不复制原文件的说明；“新建文字”为次级文字入口。
- 在同一个弹窗内切换“入口 / 待导入文件 / 新建文字 / 目录扫描预览 / 批次结果”，子视图提供返回按钮，不叠加另一层业务弹窗。仅丢弃未保存文字等破坏性操作保留必要确认。
- 文件选择、文字编辑和目录扫描各自保留临时状态；切换不会默默丢弃。准备启动另一类任务时需显式确认当前待办的处理方式，不把文件复制和目录引用混成一次提交。
- 使用带标题关联的模态对话框语义；打开后焦点进入弹窗，Tab 限制在弹窗内，关闭后返回添加按钮。Escape 和关闭按钮遵守未保存内容确认规则；有待选文件或扫描结果时不允许点遮罩静默丢弃。
- 第一阶段只启用文件与文字流程；目录入口显示“目录引用导入将在下一阶段提供”的说明，不提供无反馈的可点击按钮。第二阶段接入后启用目录选择与预览，完整布局按上图验收。

### 4.3 图片与文本文件导入

流程：点击“＋ 添加” → 拖拽文件或点击“选择文件” → 在同一弹窗校验并展示待导入列表 → 点击“开始导入” → 后台逐项入库并展示批次结果。

- 拖拽和文件选择共用待导入列表及校验规则，展示文件名、类型、大小、可导入数量和异常原因；允许移除误选项，无有效文件时不能开始。不再另弹确认框。
- 首期复用现有 20 个文件的交互上限，超出时提示分批；目录任务使用独立队列，不继承这个总数上限。
- 首版拖拽区仅接受文件；拖入目录时提示“请点击导入目录，以引用方式添加”，不得自动展开并复制。混合拖入时保留有效文件并逐项提示跳过的目录及不支持项；阶段一目录功能尚不可用时改为显示下一阶段提供的说明。
- Tauri 原生拖放提供真实路径，由 Rust 校验并生成与文件选择一致的短期令牌；不能只用浏览器 `File` 对象模拟上传，也不向前端开放通用文件系统权限。拖放仅在当前主窗口弹窗的有效区域接收，处理窗口坐标与缩放，不误触发弹窗外或悬浮球的导入。
- 新增原生拖放接入层需解除重复监听，防止同一次投放既触发旧流程又进入待导入列表；关闭弹窗后释放相关监听与暂存令牌。
- 来源记录为“手动导入 + 原文件名”，不要照搬“当前前台窗口”作为来源。
- 取消文件选择器是正常操作，不显示失败 Toast。
- 文件导入不删除用户原文件。图片标准化后的副本可能与输入文件字节不同，文案不承诺逐字节保留原图。

### 4.4 新建文字

点击弹窗底部“新建文字”，在同一弹窗内切换到编辑表单，包含：可选标题、必填正文、可选标签、字符计数、“添加”与“返回”。

- 空白正文不可提交；沿用 10,000 字符限制，超出时明确提示，不静默截断。
- 支持多行、粘贴，`Ctrl+Enter` 提交；普通 Enter 继续换行。
- 本入口明确创建文字，不因内容像 URL 就偷偷转成链接素材。
- 生成 UTF-8 文本资产并进入既有索引流程；标题、正文、备注和标签各自保持独立语义。
- 处理中禁止重复提交；失败保留输入内容；关闭有改动的弹窗时提供丢弃确认。

### 4.5 目录导入向导

点击“导入目录”调用系统目录选择器；取消后保留原弹窗状态。选定目录后在当前弹窗内切换到扫描与预览视图，不再打开独立目录业务弹窗。

```text
导入目录
目录：D:\资料\论文                              [选择目录]
导入方式：引用原文件（不复制）
☑ 包含子目录          ☐ 同时允许云端 AI 增强
文件类型：☑ 图片  ☑ TXT/Markdown
排除：隐藏/系统目录、.git、node_modules、target、dist，以及重解析点

扫描结果：可导入 368 项 · 不支持 42 项 · 超限 3 项
原文件合计：2.3 GiB（不计入素材库占用）
新增占用：缩略图、文本解码缓存、全文索引和向量缓存（另计）
提示：移动或删除原目录后，需要重新定位。VisRecall 不会删除原文件。

[取消]                                         [开始导入]
```

向导分“选目录 → 后台扫描预览 → 确认 → 后台导入”四步：

1. 默认包含子目录；提供固定排除规则，首版不加入复杂的 Gitignore 规则编辑器。
2. 扫描可取消，显示已发现数量；结果分页预览，不一次发送整个清单给前端。
3. 展示候选、已存在、不支持、超限、无权限的数量及样例；失败路径仅主动展开时显示。
4. 原文件总大小是逻辑体积，不是精确节省的实际磁盘空间，不能混淆宣传。
5. 拒绝盘符根、系统目录、应用数据目录及与素材库根重叠的目录，提示选择具体资料目录。
6. 云端 AI 默认不勾选；即使现有云端开关开启，也额外解释批量分析会发送哪些内容。

### 4.6 任务反馈与目录管理

- 状态栏显示“导入 126 / 368”，可展开任务面板；关闭面板不等于取消任务。
- 弹窗提交期间禁止重复启动同一批次；展示进度、成功 / 跳过 / 失败数量，并可展开逐项原因、重试失败项。关闭已启动任务的弹窗不等于取消任务，再打开可从任务面板查看进度。
- 素材立即可见；“已建立引用”和“内容索引完成”分别计数，不能把登记元数据说成已可全文检索。
- 允许取消未处理项，已完成项保留；单文件失败不使整个目录失败。
- 设置增加“导入目录”管理区：路径、数量、最后同步、可用状态，以及刷新、重新定位、移除操作。
- 详情显示“引用文件”、来源目录、相对路径、最后索引时间，提供打开原文件及所在目录。
- 按钮、弹窗和子视图支持键盘、Escape 和焦点返回；进度用克制的 `aria-live` 提示，不逐文件刷屏。

## 5. 存储模型：原件与派生数据分开

### 5.1 所有权规则

| 数据 | 所有者 | 存储位置 | 可否由 VisRecall 自动删除 |
| --- | --- | --- | --- |
| 截图、单文件导入副本、手动文字 | VisRecall | 库内 `originals/`、`texts/` 等 | 可以，按用户确认及现有策略 |
| 引用目录的原图、TXT/Markdown 文件 | 用户 | 用户选择的外部目录 | **不可以** |
| 缩略图、文本解码缓存、OCR 结果、索引、向量 | VisRecall | 库内派生数据区 | 可以，按清理策略重建或删除 |

“不复制原文件”不等于零占用。缩略图、必要的文本解码缓存、OCR 结果和索引仍需要空间；分别展示“素材库实际占用”与“外部引用原文件体积”，后者不计入现有容量配额。

### 5.2 建议新增的数据结构

下表是逻辑模型，不是可以直接执行的迁移 SQL；落地时按现有字段映射和事务规范细化。

| 表 / 字段 | 主要内容 | 约束 |
| --- | --- | --- |
| `items.storage_mode` | `managed` / `reference`，旧记录默认 `managed` | 不复用 `source_app` 猜测文件归属 |
| `import_sources` | ID、规范化根路径、路径身份键、包含子目录、文件类型、排除规则、AI 授权、状态、最后完整扫描时间 | 首版拒绝重复或父子重叠的导入根 |
| `external_assets` | `item_id`、`source_id`、相对路径、路径身份键、大小、修改时间、可选文件 ID、已索引哈希、来源状态 | `item_id` 唯一；同来源同路径唯一；仅用于引用素材 |
| `import_tasks` | 任务 ID、来源、状态、扫描/导入计数、错误概况、取消标记、时间 | 用于批次编排，不与现有素材 AI `jobs` 混用 |
| `import_task_entries` | 候选相对路径、预检信息、处理状态、重试次数、错误码 | 分页读取；不把百万文件列表放入内存或事件 |
| `source_exclusions` | 来源 ID、被用户主动移除的文件相对路径 | 后续刷新不自动把已移除素材加回来 |

为了减少复杂度，**单文件导入仅采用托管模式；目录导入仅采用引用模式**。首版不增加四种模式组合，也暂不支持脱离目录来源的单文件引用。

引用素材的 `original_path` 保持空字符串，不存绝对路径；真实位置仅由 `import_sources.root_path + external_assets.relative_path` 计算。托管素材继续遵守 `original_path` 为库内相对路径的约定。

数据库至少保持以下不变量：

- `managed` 素材没有 `external_assets`；`reference` 素材必须恰有一条对应记录；素材与引用记录同事务创建。
- 来源删除前必须处理关联素材；不能只级联删除路径映射、留下失去定位信息的素材。
- “来源是否可读”独立于 `items.status`；解析成功但 U 盘离线不等于解析失败。
- 任务重试按来源和路径幂等；取消后重试不能产生重复条目。
- 根目录去重采用实际路径身份规则，不无条件对所有路径小写；不支持的大小写敏感目录需明确拒绝或单独适配。

### 5.3 迁移与兼容

- 在当前三条迁移后追加新迁移，旧记录统一视为托管素材，保证截图、链接、已有文字仍可读取。
- 第一阶段按需增加任务表；第二阶段增加目录来源、外部引用和存储模式字段，分别追加对应迁移。
- 保持 `ItemKind` 和 `items.kind` 的 `image/text/link` 取值及现有 SQL `CHECK` 不变，不为新增文档类型重建素材表。
- 验证标签、FTS、向量、`revision`、触发器、索引和外键在迁移后完整，不能重建时丢失已有数据。
- 新结构不承诺旧应用安全读写。增加最低兼容版本 / 库格式检查，旧应用不能继续按旧删除语义打开新库。

## 6. 后端结构与统一读取

### 6.1 总体链路

```text
主界面按钮 / 新建文字 / 悬浮球 / 目录扫描
                  ↓
            ImportService
       校验、来源、去重、批次编排
             ↙          ↘
      ManagedImport    ReferenceImport
      保存库内资产       只登记外部资产
             ↘          ↙
          素材表 + 持久化任务
                  ↓
              AssetReader
       按素材 ID 判定所有权并安全读取
                  ↓
      缩略图 / 文本解码 / OCR / FTS / 向量
```

不要把目录展开后每 20 个文件调用一次 `DropContent::Files` 就认为完成：它仍会复制原文件，且无法表达来源、同步、恢复和批量进度。

### 6.2 核心服务职责

- `ImportService`：统一请求，区分交互来源、保存方式与解析策略；保留现有拖放兼容适配。
- `DirectoryImportService`：流式扫描、过滤、候选、同步差异、来源状态与重新定位。
- `AssetReader`：按素材 ID 返回经过校验的读取句柄、字节或路径；托管与引用显式分支。
- `ImportTaskRepository`：任务与候选项持久化、取消、重试、进度查询。

`AssetReader` 放在 app-core 和 pipeline 均可依赖的低层，例如 `crates/library/src/assets.rs`；不能让 pipeline 反向依赖 app-core 造成循环依赖。

统一读取必须覆盖：原图预览、缩略图、详情文字、复制内容、打开原文件、OCR、VLM、全文索引、重新解析。不能只改原图预览函数。

### 6.3 IPC 建议

以下是拟新增接口，不表示仓库已有对应命令；参数类型通过 Specta 导出。

| 命令 | 输入 / 输出要点 |
| --- | --- |
| `pick_import_files` | Rust 原生多选 → 后端保存的短期选择令牌和展示摘要；取消返回空值 |
| `start_file_import` | 原生选择或拖放产生的选择令牌、选中条目标识 → 批次任务 ID；不接收任意绝对路径，提交前重新校验 |
| `create_text_item` | 可选标题、正文、标签 → 素材 ID |
| `pick_import_directory` | Rust 原生目录选择 → 令牌与展示路径；不影响已有库迁移选择器 |
| `scan_import_directory` | 选择令牌、扫描选项 → 扫描任务 ID |
| `start_directory_import` | 扫描任务 ID、确认选项 → 导入任务 ID |
| `get_import_task` / `list_import_task_entries` | ID、游标、页大小 → 权威进度 / 分页详情 |
| `cancel_import_task` / `retry_import_task` | 任务 ID → 更新后状态 |
| `list_import_sources` / `refresh_import_source` | 来源列表 / 来源 ID → 刷新任务 |
| `relocate_import_source` | 来源 ID、新选择令牌 → 校验结果，确认后更新根路径 |
| `remove_import_source` | 来源 ID、是否移除关联索引 → 结果；保留条目时只停用来源，不删路径映射 |

沿用 Rust 侧 dialog；文件选择器支持多文件选择，无需为入口给前端开放通用文件系统权限。[R3]

原生拖放由 Rust 侧接收路径、校验目标区域及文件，再保存为与文件选择共用的短期令牌。只向对应窗口发送 `import_drop_ready` 通知，包含令牌、文件展示摘要及跳过原因；前端不能自行提交任意路径冒充用户投放。令牌应绑定窗口、限制有效期并在提交或丢弃后失效；前端移除误选项时仅提交该令牌下的条目标识。

`import_task_progress`、`import_task_finished` 事件只传任务 ID、计数、状态，不传正文或全部路径。事件通知刷新，任务查询才是权威状态，避免漏事件后进度永久丢失。

现有素材事件继续使用；批量导入时，前端按短时间窗口合并缓存失效，避免每个文件都重置列表、重新搜索。

### 6.4 队列与限制

- 扫描、导入放到后台 worker，不阻塞 UI、悬浮球和截图；不为每个文件创建无上限线程。
- 初始扫描并发 1、文件处理并发 2；云端 AI 独立限流，保证用户新截图任务不被大批目录任务长期阻塞。
- 建议最多 50,000 个候选文件、深度 32；达到上限停止，要求缩小范围，不静默截掉剩余文件。
- 图片、TXT/MD、文字输入沿用当前大小限制；引用模式也检查，不复制不等于可以无限量解码。
- 图片按头部尺寸限制解码像素总量，不能只在解码后缩小；具体像素阈值由第二阶段内存测试固定。
- 扫描不读取所有文件全文；导入时逐文件计算哈希；前后检查大小、修改时间，变化则重试或标记不稳定。
- 取消在安全边界生效；已提交素材保留，未完成临时文件清理；取消不能把未扫描到的旧素材判定为丢失。
- 重启将残留 `running` 任务标记中断，展示继续 / 重试，不自动触发整库扫描或大批 AI 请求。

## 7. 目录同步、去重与失效恢复

### 7.1 首版同步策略

采用 **首次扫描 + 用户主动刷新 + 读取时校验**，不立即引入全目录实时 watcher。

| 变化 | 行为 |
| --- | --- |
| 新增文件 | 过滤、去重后建立引用，进入本地索引队列 |
| 文件未变化 | 跳过，不重复解码、OCR 或请求云端 AI |
| 内容修改 | 保留 ID、备注与手工标签；增加 `revision`，重建派生数据 |
| 文件删除 | 标记 `missing`，保留备注、摘要和索引，显示“原文件不可用” |
| 无权限 | 标记 `permission_denied`，与不存在区分，允许修复后重试 |
| 整个目录离线 | 来源标记离线，不因一次失败刷新就删除全部素材 |
| 用户从库移除一项 | 写入排除记录；提供恢复已忽略文件入口 |
| 文件重命名 / 移动 | 首版按旧路径缺失、新路径新增；仅在身份或哈希唯一且可验证时合并 |

只有完整成功扫描，才能判断哪些路径本次已不存在。无权限、取消、临时离线时，不做缺失批处理。

### 7.2 去重边界

- 同来源同相对路径：更新已有素材，不重复创建。
- 重复或父子重叠导入根：首版拒绝并指向现有来源，不立即实现多来源成员关系。
- 同内容不同路径：允许独立条目，不自动合并来源和备注；哈希相同不等于共用素材 ID。
- 托管与引用内容相同：保留模式差异，提示可能重复，不自动删除托管副本。
- 相同内容缓存共享属于后续优化，需另做引用计数，本方案不依赖它达成基本节省目标。

### 7.3 重新定位

目录移动后，选择新根目录：抽样检查相对路径、大小、哈希，展示匹配比例；只在确认后更新来源。

- 不因选中新目录就立刻覆盖路径；同名不同内容保持待确认 / 已变更状态。
- 不能把旧索引直接显示为最新结果；不得主动扫描整块磁盘寻找用户资料。

### 7.4 内容版本与缓存

外部文件可变，现有“素材 ID 对应不可变原图”的假设不再成立：

- `content_hash` 表示已接受处理的内容版本；检测修改后增加 `revision` 并安排任务。
- 索引、缩略图、文本缓存提交前检查 revision；旧任务不能覆盖新结果。
- 使用一致读取快照或前后校验，防止索引对应旧字节、预览对应新字节却没有提示。
- 原图 / 缩略图请求携带版本；引用原件不沿用只按 ID 的永久不可变缓存，后端策略与前端 URL 一起调整。
- 图片变化后重建 OCR 坐标；新原图就绪、OCR 未更新时，不画旧框。
- 缺失时显示缓存缩略图及“来自上次索引”，不伪装原件仍在线。

## 8. 支持类型与处理边界

### 8.1 文件类型与处理路径

| 类型 | 计划支持 | 索引方式 | 原文件预览 |
| --- | --- | --- | --- |
| PNG/JPG/JPEG/WebP/GIF | 第一阶段，引用在第二阶段 | 现有 OCR + 索引；AI 按授权启用 | 原图；引用不写入原图副本 |
| TXT/MD | 第一阶段，引用在第二阶段 | 复用现有解码，统一为 UTF-8 派生内容后索引 | 文本预览 |
| 手动文字 | 第一阶段 | 本地 UTF-8 原文 + 既有索引 | 正文 |
| PDF/DOCX 等独立文档格式、Office 文件、压缩包 | 不支持，也不纳入本方案的后续增强 | 目录扫描时跳过并说明，不创建素材或解析任务 | 不提供入口 |

保持现有 `image/text/link` 素材类型。TXT/Markdown 和手动文字仍使用 `text`，不新增独立文档类型；已有链接导入行为保持不变，不在本轮增加链接入口。

### 8.2 既有处理能力与限制

- 图片复用既有解码、缩略图、OCR、索引管线；引用模式只读原图，不保存原图副本。
- TXT/MD 复用已有编码识别和解码能力；仅在需要时保存 UTF-8 派生缓存，不覆盖外部原文件。
- 图片大小、文本文件大小和手动文字字符限制沿用第 2 节现有值，不新增专用文档解析器或解析依赖。
- 文字索引沿用现有 10,000 字符上限；超过时明确提示“仅前 10,000 字符参与检索”，不宣称全文已完整索引。
- 不支持类型在单文件选择器中过滤，在目录扫描结果中列为跳过，不读取二进制内容作为文本。

## 9. 安全、隐私与生命周期

### 9.1 只读与路径安全

1. 外部资产仅通过来源 ID 和相对路径访问；前端不能提交任意绝对路径要求读取。
2. 相对路径拒绝 `..`、绝对路径、设备路径、替代数据流等逃逸形式；先校验输入，再解析路径。
3. 默认跳过符号链接、Junction 等重解析点；仅用 `is_symlink()` 不能声称覆盖全部 Windows 重解析点。
4. 打开时核验最终文件句柄仍指向授权根内对象，防止扫描后目录被替换为链接的检查与使用间竞态。
5. 首版不支持 UNC 网络根；本地云盘占位文件默认跳过，提示先下载。“不上传”不代表完全不会发生网络或磁盘同步。
6. 保留库内路径安全校验；引用读取不能靠放宽全局 `relative_to_root` 规则实现。
7. `visrecall://` 仍只接受素材 ID 与受控版本参数，不开放任意文件读取或目录枚举。

### 9.2 删除、容量、保留与迁移

| 操作 | 托管素材 | 引用素材 |
| --- | --- | --- |
| 删除素材 | 按已有机制删除库内记录 / 自有资产 | 删除记录与派生缓存，写入来源排除项；不碰原件 |
| 移除来源 | 不适用 | 可仅停用同步保留条目，或移除关联条目；均不删除原目录 |
| 清空库 | 清理自有数据 | 清理引用和派生数据，移除 / 停用来源任务，避免刷新后恢复 |
| 容量清理 | 沿用受控库内清理 | 不计原件大小、不删原件；可清派生缓存，必要时暂停新建索引 |
| 自动保留 | 沿用已有行为 | 首版默认不自动移除目录引用；后续仅显式启用 |
| 迁移库 | 迁移自有资产和数据库 | 迁移元数据及缓存；不复制、不移动原件，完成后检查来源 |
| 备份 | 可包含自有资产 | 默认只含引用和缓存，明确不含外部原件；完整归档另做 |

**保护底线：** 删除 API 按所有权分流；外部资产接口不提供写入、删除或移动原件的方法。不能 UI 写着“仅删除索引”，实际却调用 `remove_file(external_path)`。

### 9.3 本地索引不等于不会出网

已有 AI 增强可能调用云端。目录默认只做本地可用的文本解码、OCR、FTS、嵌入；嵌入也需确认是本地后端，不能仅按功能名称认定本地。

云端分析由来源级授权和全局隐私设置共同允许，全局禁止优先。文案说明可能发送原图、OCR / 文本内容或摘要，给出估计任务量，并允许暂停。

- Tauri 实机：拖放真实路径、目标区域与缩放、弹窗外不接收、重复监听清理、混合拖入目录与文件的提示、选择令牌窗口绑定和过期；确认既有悬浮球拖放不回归。
- 核心：多文件结果、正确来源、引用不落原件、过滤、数量上限、取消幂等。
- 安全：中文和空格、长路径、大小写、穿越、链接环、Junction、扫描后替换重解析点、无权限、云盘占位、禁用 UNC。
- 生命周期：删除、清空、保留、容量、孤儿清理、迁移后逐一断言外部原件存在且哈希一致。
- 同步：新增、修改、删除、离线、定位、排除、中断；旧 revision 不能覆盖新内容。
- 文本与类型过滤：中文 TXT/MD、编码兼容、空白输入、超长文字索引提示、不支持类型跳过且不创建素材。
- 迁移：旧库样本验证素材、备注、标签、FTS、向量可读，最低版本检查有效。

Windows 链接测试按能力探测启用；不能因普通用户无法创建测试链接使全套误报失败；Junction 与符号链接覆盖分别报告。

### 11.3 产品验收

- [ ] 不使用悬浮球，在主窗口添加图片、TXT/Markdown 文件和文字。
- [ ] 空库、普通列表、搜索结果都能找到入口。
- [ ] 添加按钮位于搜索框右侧且不遮挡搜索内部操作；窄窗口和明暗主题下布局可用。
- [ ] 同一弹窗支持拖拽文件、点击选择文件、点击选择目录和新建文字，不叠加业务弹窗。
- [ ] 拖拽与选择文件共用待导入列表，可移除误选项；不支持项明确提示，弹窗外拖放不触发新流程。
- [ ] 目录操作明确提示引用、不复制；先扫描预览再确认，拖入目录不得自动复制。
- [ ] 键盘可完成主要操作，关闭后焦点返回入口；取消选择不报错，导入不清空查询，未保存内容不被静默丢弃。
- [ ] 引用导入 1,000 个测试文件后，没有对应原件副本，占用只来自数据库及派生数据。
- [ ] 10,000 个小文件目录采用分页扫描和进度，窗口可交互，截图仍可用。
- [ ] 取消保留已完成项，重试不重复；重启不自动启动大批云端分析。
- [ ] 删除、移除来源、清库、容量清理、迁移均不修改或删除引用原件。
- [ ] 拔盘、移动目录后状态可恢复，而非崩溃或全量删除。
- [ ] 文件更新后刷新内容和预览，旧 OCR 框不叠在新图上。
- [ ] 仅接受支持的图片及 TXT/MD；其他格式明确跳过，不建立专用文档解析任务。
- [ ] 超长文本明确提示索引范围，不把截取索引宣称为全文索引。
- [ ] 云端 AI 默认关闭，来源单独授权后才按全局隐私设置执行。

## 12. 开发前可确认的产品选项

本方案已给默认值，不作为本次文档交付的阻断问题：

| 选项 | 推荐默认值 | 调整影响 |
| --- | --- | --- |
| 自动监控目录 | 手动刷新 | 自动监控增加 watcher 生命周期、资源限制、去抖复杂度 |
| 系统软链接 | 不使用，应用层引用 | 真链接增加平台、权限、清理验证成本 |
| 目录复制模式 | 首版不提供 | 增加后需处理所有权、同步和备份语义 |
| 自动清理失效项 | 不自动清理 | 避免把临时离线当成删除 |
| 自动云端 AI | 默认不调用 | 启用需来源授权、任务量提示和独立限流 |
