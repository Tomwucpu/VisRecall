v2.10 修订记录

F5.3 改为原始内容复制：主复制按钮不再输出「摘要 + 原图」的组合，而是按素材类型直接复制原始内容——图片复制原图（原分辨率），文本复制原文纯文本，链接复制原始 URL。摘要、标签、来源不混入主复制结果，避免用户粘贴后还要手动删改。

摘要独立复制：详情页「AI 描述 / 摘要」标题旁新增小复制按钮，只复制摘要文本；摘要缺失或待解析时不可用。复制成功给轻提示。

连带调整：F5.3 名称改为「原始内容复制」，主按钮按类型显示「复制原图 / 复制原文 / 复制链接」，验收标准按素材类型重写；8.1 详情页线框补充摘要复制按钮；JTBD 对应功能文案同步。原「富文本保留图片 / 纯文本复制摘要与链接」的双模式取消。

v2.9 修订记录

进口体积闸门重定：图片 50MB → 20MB，文本 1MB → 500KB。原 50MB 在任何口径下都不成立——实测五家视觉 API 的单图上限为 Claude 5MB、OpenAI / Gemini / 通义 20MB、DeepSeek 32MiB，无一家接受 50MB；且 50MB 的 JPEG 解码需 400MB–1GB，与「常驻内存 ≤ 150MB」冲突。

20MB 的依据：它是「所有厂商都能接受」与「本地解码内存可控」的唯一交集。而各家模型内部实际使用的分辨率只有 1300–3072px（DeepSeek 约 1300、OpenAI 2048、Gemini 3072），上传体积与理解质量本就脱钩。

500KB 的依据：约 17 万汉字，正好对应主流模型 128K 的上下文长度。超过这个量，一条素材只能分段摘要，而分段必然丢结构。

新增自动降采样：长边超过 8000px 的图片自动缩放后入库，不拒绝也不提示。体积是用户能理解的量，像素是用户不关心的量，后者交给系统处理。

片段超限改为拒绝：拖拽选中的文本片段超过 1 万字符时直接拒绝，不再截断保留。截断会让用户误以为整段内容已入库，与文本文件超限的处理保持一致；提示实际字符数与上限，建议拆分后分别存入。

v2.8 修订记录

F1.7 剪贴板捕获改为默认关闭：须在设置中手动启用。剪贴板是全局共享资源，常驻监听意味着程序会持续读取用户复制的所有内容（含密码、验证码、私密文本），这与「只在用户显式操作时采集」的 D1 不一致，因此不设默认值。

验收标准补硬要求：默认状态下不注册任何剪贴板监听、进程不读取剪贴板内容；关闭开关后立即注销监听并清空已读取内容。「关闭」必须是真关闭，不是停止提示但继续读。

设置分区调整：「快捷键」扩展为「捕获」，统一管理快捷键、悬浮球显示与剪贴板开关；信息架构图对应子项同步。开启时须明示「这会读取你复制的图片」。

01产品定位与边界

一句话定位：一个把「屏幕上看到的、白板上写的、纸上印的」视觉信息，在 2 秒内存进来、用一句话找回去、并一键变成可编辑文档的桌面工具。

它不是屏幕录像机，不是截图管理工具，也不是笔记软件。它的价值集中在三段：极低摩擦的入库、基于模糊记忆的召回、向知识库的沉淀。

1.1 明确不做的事

不做原因
任何形式的自动捕获包括 7×24 全屏录制，以及「仅对指定应用按间隔自动捕获」这类折中方案。资源占用、隐私信任、合规审查三重风险叠加，Rewind 已验证失败。产品只接受用户显式发起的采集
麦克风与会议录音与 Otter、飞书妙记等成熟工具正面竞争，且显著提高合规成本
力导向知识图谱可视化个人知识管理场景中普遍「好看不好用」，V2 前不投入
在线协作与团队共享属企业版范畴，独立产品阶段不做
移动端应用与手机扫码上传本期整体移除。白板与纸质场景先由「图片文件拖入悬浮球 + 系统截图」覆盖，待桌面端跑通留存后再评估
富文本编辑与长文写作文本素材只承载「片段」，不做编辑器。避免产品漂移为笔记工具（见 D7）
每日简报与自动总结暂不做。自动生成的日汇总回访率普遍偏低，且会把产品拉向知识管理赛道。保留「主题卡片」作为 P2 观察项，待检索数据充分后再评估是否需要定时回顾
第三方双向同步暂不做。只支持单向导出到用户指定目录。同步需处理冲突、路径映射、增量更新与失败重试，工程成本数倍于导出，还会引入数据归属的模糊地带
预先排除规则暂不做。手动捕获下用户清楚自己在截什么，系统抢在用户之前拒绝执行反而制造困惑
敏感信息识别与拦截暂不做。判断「什么算敏感」既需要规则库，也需要置信度阈值，误判无法避免；一旦拦错，用户会认为工具不可靠，而不认为它是在保护自己。手动捕获下控制权本来就在用户手上——看见不该留的内容就别按快门，截错了用「彻底删除」处理。产品对隐私的承诺收缩为两条：数据去哪可以查到，数据删掉就真的没了
重复检测与去重暂不做。检测本身不难，难在判定之后怎么办：弹窗裁决会打断连续截图的节奏，静默丢弃又可能误杀真实需求（用户可能是故意重截，因为价格变了、主题切了、想留两个版本对比）。本版两种都不做，重复画面按普通素材入库。代价是库里可能出现内容相近的多张图，并各付一次解析费用；用户浏览时可自行清理
PDF 与 Office 文档导入本期只收图片与纯文本（.txt / .md）。PDF 要分「有文字层」与「扫描件」两条路径，还要额外处理分页、表格、公式与版式还原，工作量接近再做一个垂直产品；而这类内容用户已经在用专业工具管理。屏幕上正在看的 PDF 页，截屏即可覆盖
macOS 与 Linux 版本本期只做 Windows。窗口识别、悬浮窗置顶、全局快捷键、开机自启、凭据存储、高 DPI 缩放这六件事在每个系统上都要单独实现且行为不同，跨平台会让 MVP 工期接近翻倍，而验证产品价值不需要第二个平台

1.2 边界说明

产品只负责「视觉信息的记忆与复用」，不负责用户的日程、任务与写作。数据全部存放在本机的普通文件夹中，图片与文本均为标准格式，路径在设置里可见、可打开、可更改：想交给其他工具，用「开放格式导出」；想换台电脑继续用，用「数据迁移包」完整搬移。不隐藏、不托管、不限制带走——这是产品承诺，也是信任基础。

03产品原则

1
捕获必须快过犹豫
从点击悬浮球（或拖入内容）到素材入库，用户不应做任何决策——分类、命名、打标全部由系统完成，用户只在事后修正。这里要区分：快指的是没有认知负担，不是没有物理动作。截屏的四个阶段都是手上的动作，不需要判断，因此不违背这条原则；而「先选个文件夹」需要用户思考归属，一次就足以让人放弃。
2
检索结果要能解释为什么命中
每条结果下方显示「因为匹配：橙色 · 图表 · 定价页」。用户对搜索的信任来自可理解性，而非排名本身。这同时是检索质量的自我暴露，便于收集反馈。
3
默认最保守的隐私设置
默认不自动采集、不录音、不含境外模型、不联网也能用。所有「更便利」的选项都需要用户主动开启，且开启时必须明确告知数据去向。
4
失败要可见，不能静默降级
模型调用失败、图片解析失败、离线状态，都必须在卡片上以「待解析 / 解析失败」明确标识，并提供重试入口。用户最不能接受的是「东西存进去了但搜不到，而且不知道为什么」。
5
数据主权属于用户
本地存储、开放格式、一键完整导出、一键彻底删除。任何云端依赖都必须是可选增强，不能是功能前提。

04关键设计决策

以下决策直接影响产品形态，需在开发前确认，后续变更需重新评审。

D1捕获方式：只做主动捕获，不提供任何自动采集
理由是同时降成本、降合规风险、提升检索准确率（主动捕获的图都有明确上下文）。原计划保留的「白名单应用间隔捕获」也已取消：一旦系统里存在「自动」这个开关，用户就会默认它可靠，而屏幕内容的不可预测性决定了这类功能永远不可靠——漏拍的那一刻，往往正是需要它的那一刻。代价：彻底失去「记录一切」的叙事吸引力，必须靠更强的场景化引导建立使用习惯。
D2入库不需分类，分类是事后行为
捕获后进入统一的「收件箱」，系统自动打标。用户可在详情页或批量操作中归入「合集」。代价：收件箱会堆积，需要「每周回顾」机制辅助清理。
D3检索采用「一个框 + 筛选器」，不做独立的高级搜索页
自然语言输入即检索，同时解析出时间、应用、颜色等条件并以可删除的 chip 形式回显，用户可手动修正。代价：查询解析错误时需用户介入，因此 chip 必须显眼可编辑。
D4模型默认国内厂商，本地模型作为一等选项
规避数据出境合规问题，同时保证离线可用。代价：首次配置需要用户填写 API Key，需提供引导与免费额度过渡方案。
D5知识沉淀以「导出」为主，不做内置知识库
避免与 Obsidian、ima 等产品正面竞争。产品负责「捕获与找回」，沉淀交给用户已有的工具。因此本期只做导出、不做双向同步——单向写出的成本是同步的十分之一，且不存在冲突与数据归属问题。代价：产品闭环感弱，需通过导出质量与格式兼容性弥补。
D6悬浮球与快捷键完全等价，且可关闭
悬浮球解决两个具体问题：快捷键记不住，以及从浏览器拖文字时「没有落点」。但它是可见的常驻元素，必然有用户嫌它碍事。因此：两者功能等价、任意其一可独立使用、悬浮球可完全隐藏，产品不依赖它存在。代价：需要维护两条入口的交互一致性，任何新增捕获能力都要在球上给出对应手势。
D7文本素材是副产品，不发展成体系
支持拖入文字之后，产品已经具备「笔记工具」的雏形，这是危险的滑坡。因此设定硬边界：拖拽选中的文本片段单条 ≤ 10000 字符，导入的 .txt / .md 文件单文件 ≤ 500KB（约 17 万汉字，正好对应主流模型 128K 的上下文长度——超过这个量，一条素材就只能分段摘要，而分段必然丢结构）；两者都无富文本、无编辑历史、不提供独立的「笔记」入口，文本素材只能出现在素材流与检索结果中。它是「被检索到的东西」，不是「被书写的东西」。

文件上限高于片段，是因为两者的规模预期不同：片段是「顺手存一段」，文件是「把已有的东西放进来」。但真正的界线不是长度，而是能不能在这里编辑——这一条始终为零。只要编辑器不出现，文本量再大也只是被检索的对象，不会变成写作工具。代价：部分用户会提出「能不能在这里直接写」，需明确拒绝。
D8截屏必须有确认步骤，不做「松手即提交」
这是产品里唯一刻意增加操作步数的地方。框选是不可逆的模糊操作，松手即定，偏一点就要重来；而一次确认只需 0.5 秒。「可调整长宽」这一能力也必须有提交点才能成立——否则调整与提交的边界无法区分。因此：识别、选择、调整、提交四阶段为默认流程，确认通过 Enter 或 ✓ 完成。代价：单次捕获增加约 0.5–1 秒；高频用户（日均 20 次以上）会感到累赘。缓解方式是在设置中提供「松手即提交」开关（P1，默认关闭），并保留 Enter 作为最快确认路径。
D9数据放在用户可见的本地目录，不隐藏、不托管
这个产品会积累大量个人屏幕内容，因此「数据在哪」必须随时能回答。三个要求：路径可见、格式标准、随时可带走。

具体做法：库文件、原图与索引全部落在用户可见的普通文件夹中，设置里直接显示路径并可一键打开；支持整体更换存储位置，例如从系统盘搬到数据盘；出口有两条——开放格式导出用于交给其他工具，迁移包用于换机继续用。不做隐藏目录、不做私有格式、不做服务端托管。代价：文件以可直接读取的形式存在于磁盘，任何能访问该磁盘的用户或程序都能读取。这一点需在数据流向页如实写明，不藏在条款里。

需要区分两个概念：迁移是一次性的单向搬移，多设备同步是持续的双向合并。本期只做前者。若用户要求「两台电脑同时用」，那本质是同步问题，需要冲突合并策略，不在范围内。

05信息架构

产品由五个入口构成：悬浮球（桌面常驻的可见捕获入口，同时是拖放目标）、快捷键（与悬浮球完全等价的键盘路径）、主窗口（检索与整理）、托盘菜单（状态与快速控制）、设置（独立窗口，默认不主动弹出）。

6.1.1 选区与调整态规格

截屏是四个阶段的连续过程：识别 → 选择 → 调整 → 提交。前三个阶段在同一次全屏覆盖层中完成，不切换界面。

进入选区态的瞬间，系统先抓取一帧全屏画面并冻结，此后所有识别、框选与调整都在这张静态帧上进行。用户看到并框选的内容，与实际截取的内容始终是同一帧——中间不会因为视频播放、页面滚动或倒计时跳变而错位。这解决的是一个必然发生的问题：从按下快捷键到确认提交之间有几秒钟，屏幕上的东西是会变的，而用户想留下的，恰恰是他按下快门时看到的那一瞬。

阶段用户动作系统响应视觉反馈
识别 鼠标在屏幕上移动 实时识别指针下的窗口；位于桌面空白处时识别为整屏 半透明高亮覆盖该窗口，右上角标签显示窗口标题与尺寸
选择 单击高亮窗口；或直接拖拽画框 单击时吸附到窗口边界；拖拽时采用自定义矩形 实线选区 + 八个控制点出现，尺寸标签固定显示
调整 拖控制点改长宽；拖选区内部整体移动；方向键微调 实时更新选区几何，并重新取景 宽高数值实时刷新；靠近窗口边缘 8px 时自动吸附对齐
提交 按 Enter 或点击 ✓ 从冻结帧中裁出选区，开始上传与解析 选区消失，右下角浮层出现缩略图与备注框

关键规则

  • 画面冻结：抓帧与进入选区态在同一步完成，用户不会先看到一个「活」的界面再被冻结。冻结后，选区外的区域做压暗处理，这本身就在传达「画面已停止」；角落另显示一次性角标「已冻结」，3 秒后淡出。
  • 不提供重新抓帧：冻结帧一旦生成，本次截屏内不再更新。若用户发现想截的是变化后的画面，按 Esc 取消、再重新触发一次截屏即可，代价约为一次快捷键。不在覆盖层内设置第二个取景入口，避免出现「当前这张是哪一帧」的歧义。
  • 窗口层级下钻：滚动鼠标滚轮可在指针下的父/子窗口间切换高亮层级。用于解决「识别到整个浏览器，而我只想要内容区」这类问题。这是窗口识别能否实用的分水岭。
  • 全屏入口：鼠标停在桌面空白处时高亮整屏，单击即全屏。不再单独提供「全屏截屏」按钮，全屏只是识别结果的一种。
  • 吸附与反吸附：拖拽时距窗口边缘 8px 内自动吸附对齐；按住 Ctrl 临时关闭吸附，用于需要精确到像素的场景。
  • 微调：方向键移动 1px，Shift + 方向键移动 10px。用于调整到内容边框，避免多截一条白边。
  • 最小尺寸：选区小于 10×10px 视为误触，提交时直接取消并提示「选区过小」。
  • 取消：任意阶段按 Esc 或单击右键，立即退出且不产生任何记录。
  • 多屏：允许跨屏拉出选区，但起始点须落在同一屏内；跨屏时坐标按物理像素合并计算。
唯一的例外：为什么截屏要多一步确认

本产品其余所有流程都在压缩操作步数，唯独截屏刻意保留确认。因为框选是一次不可逆的模糊操作：手指松开的那一刻，选区就定了；如果偏了 20px，代价是重新截、重新定位、可能还要重新滚动页面回去。一次确认点击约 0.5 秒，一次返工约 5–10 秒且带有挫败感。更何况「可调整长宽」这个能力本身就需要一个「调整完成」的提交点才能成立。详见 D8。

为什么允许拖入文字

用户在浏览器里读到一段话时，「选中并拖走」是他已经形成的肌肉记忆。拒绝这个动作，等于要求他先截图再回来——多一步，就会流失。接受它，成本只是多一个素材类型；拒绝它，代价是失去一个高频入口。但接受之后必须立刻划清边界（见 D7），否则产品会在半年内变成半个笔记软件。

07核心流程

7.1 截屏捕获流程

入口有两个，行为完全一致：点击悬浮球，或按下全局快捷键（默认 Ctrl+Shift+S）。整个过程在同一个覆盖层内完成，不切换界面。

  1. 触发：按下快捷键或点击悬浮球，系统在同一瞬间抓取全屏画面并冻结；屏幕进入选区态，其余区域压暗，光标变为十字。
  2. 识别：在冻结帧上，指针下的窗口被识别并以半透明高亮，标签显示窗口标题与尺寸；停在桌面空白处时高亮整屏。滚轮可在父/子窗口间切换层级。
  3. 选择：单击高亮窗口即采用其边界；也可以直接拖拽画出自定义矩形。
  4. 调整：选区出现八个控制点，可拖拽改长宽、拖内部整体移动、方向键做像素级微调；靠近窗口边缘时自动吸附对齐。
  5. 提交：按 Enter 或点击 ✓，此时才截取并开始上传。
  6. 入库与解析：右下角浮层出现缩略图与备注框，素材已确定入库；卡片以「解析中」状态出现在收件箱顶部，3 秒内转为正常卡片。解析在后台进行，不阻塞下一次捕获。同一画面重复捕获时按普通素材入库，不提示、不去重。
  7. 取消与异常：任意阶段按 Esc 或右键即退出，不产生记录；若想截取变化后的画面，退出后重新触发即可，无需在覆盖层内等待或切换模式。无网络或密钥失效时卡片标记「待解析」，恢复后自动重试。

7.2 拖放捕获流程

用于「手上已经有一段内容，想直接丢进来」的场景——从网页拖一段文字、从文件夹拖一张截图或一份 Markdown 笔记、从聊天窗口拖一张图。

  1. 起拖：用户在浏览器或文档中选中内容并开始拖拽。此时悬浮球若处于收起态，需在检测到拖拽经过时立即展开。
  2. 目标显现：球体进入接收态，放大至 1.15 倍，上方浮出动作提示气泡，让用户在松手前就知道「会发生什么」。
  3. 判定：系统按拖入内容给出提示——「存为图片」「存为片段」「存为链接」或「导入 3 个文件」。
  4. 松手：立即入库，球体回弹并短暂显示「已存入」（1.5 秒），不打断用户当前操作。拖放不需要确认——内容本身已经确定，不存在需要调整的几何边界。
  5. 解析：图片走完整视觉理解管线；文本走摘要、标签与全文索引，通常比图片快 1–2 秒。
  6. 取消：拖拽中途按 Esc 或移出球体，不产生任何记录。
设计要点

两条路径中，用户都只完成一个动作：框选，或松手。备注框虽然有，但默认不聚焦、不强制。落点提示必须出现在松手之前——如果用户拖进来的是一段文字却意外变成了截图，或者反过来，他下次就不会再用这个入口了。

7.3 检索流程

  1. 唤起：全局快捷键或点击托盘，主窗口置前，光标自动落在搜索框。
  2. 输入：用户输入自然语言，如「上周那个橙色图表的竞品页面」。
  3. 解析回显：搜索框下方出现 chip：时间：上周 颜色：橙色 类型：图表 语义：竞品页面。每个 chip 可单独删除或修改。
  4. 结果：卡片流按相关度排序，每张卡片下方标注命中原因，命中的 OCR 词在预览中高亮。
  5. 修正：结果不理想时，用户可直接删 chip 或用「不是这个」按钮反馈，系统据此调整并记录样本。
  6. 打开：点击卡片进入详情面板，原图大图、描述、OCR、标签、来源时间一屏可见。

7.4 沉淀流程

  1. 回顾：每周一次「收件箱回顾」提示，批量归入合集。
  2. 导出：选中素材或整个合集，导出 Markdown 与图片到指定目录。该目录可以是 Obsidian 库，也可以是任意文件夹——产品只负责写文件，不负责维护同步关系。

截取到受 DRM 保护窗口捕获结果为空，直接丢弃提示「该窗口无法截取」，不产生脏数据
窗口识别失败（无边框应用、独占全屏游戏）不显示高亮，选区态保持可用无报错，用户直接拖拽框选即可，不打断
选区小于 10×10px取消提交并退出选区态提示「选区过小，已取消」，不产生记录
冻结帧里的内容不是用户此刻想截的（页面还在加载、动画未播完）保持当前冻结帧不变，本次截屏不更新画面无额外提示；用户按 Esc 取消后重新触发截屏即可获得新的一帧
抓帧失败（独占全屏、显卡驱动异常）降级为实时取景，提交时截取当时内容角落提示「实时模式」，让用户知道画面未冻结、需自行把握提交时机
选区跨屏或超出可见区域按物理像素裁剪到可见范围，跨屏坐标合并计算尺寸标签实时显示实际可截取区域
存储空间不足（< 2GB）拒绝新的捕获，保留检索与导出功能模态提示，提供「清理旧素材」与「更换目录」两个动作
图片超过 20MB 或文本文件超过 500KB拒绝该文件，同一批次的其他文件正常导入提示具体数值与上限，如「这张图 26MB，上限 20MB」，不用「文件过大」这类笼统措辞
拖入无法识别的内容拒绝并保持球体原状（如文件夹、程序快捷方式、压缩包、PDF、Office 文档）气泡提示「暂不支持此类型」，列出支持的六种格式：PNG / JPG / WebP / GIF / TXT / MD
拖入文本超过上限选中的片段超过 1 万字符时拒绝，不入库；文本文件超过 500KB 时同样拒绝。两者都不截断片段被拒时提示「这段文字 2.3 万字符，超出单条片段 1 万字符的上限，建议拆分」；文件被拒时提示「这份文件 1.2MB，约 40 万汉字，超出单条素材的承载范围，建议拆分」
拖拽源拒绝提供内容尽力获取可用部分（如仅文件名、仅纯文本）提示「部分内容无法读取，已保存可见部分」
悬浮球与全屏应用冲突检测到全屏时自动隐藏，退出全屏后恢复原位置不显示任何提示，避免打断
显示器拔插或分辨率变化将球校正到最近的可见区域内若原位置已不存在，回到主屏右下角并保留一次淡入提示
吸附位置被任务栏占用沿边缘上移或下移避让，保持 12px 间距无提示，位置自动记忆
检索无结果展示「放宽条件」建议，并给出最近 3 条时间相近的素材「没有找到完全匹配的，试试去掉『橙色』」
应用崩溃后重启检测未完成的解析任务并恢复队列启动后提示「已恢复 3 项待解析」
迁移包版本高于当前客户端拒绝导入，不做降级兼容提示需升级客户端，并同时显示包与当前的版本号
导入时与目标库内容重复按内容哈希去重，备注与标签取并集导入完成后报告「新增 N 条 / 合并 M 条」

10数据对象定义

面向产品与设计对齐，非技术数据结构。

对象含义关键属性
素材（Item）最小单位，对应一次捕获、一次导入或一次拖放。分图片素材与文本素材两种形态类型（图片 / 文本 / 链接）、原图或原文、缩略图、来源应用、来源标题、捕获时间、宽高、状态（解析中/正常/待解析/失败）、备注
描述（Insight）系统对素材的理解结果，与素材一对一一句话摘要、内容类型、主色调、图表类型、关键实体、OCR 全文、是否含公式、生成所用模型、置信度
标签（Tag）多对多，分自动与手动两类名称、来源（自动/手动）、创建时间
合集（Collection）用户自建的主题集合，多对多名称、描述、封面、排序方式、素材数量
查询（Query）一次检索记录原始输入、解析出的条件、命中结果集、用户反馈（有用/无用）

两种素材形态共享同一套组织与检索机制，差异只在描述字段：图片素材携带主色调、图表类型等视觉属性；文本素材携带字符数与原文首段；链接素材是文本素材的子类型，额外记录抓取到的页面标题与站点名。检索时两者在同一结果流中排序，不做区分。

关于「查询」对象的说明

把每一次查询及其反馈记录下来，是为了构建自有的评测集。这个数据集会成为产品最重要的资产——它能告诉你真实用户如何描述视觉记忆，而这一点没有任何公开数据可以替代。
